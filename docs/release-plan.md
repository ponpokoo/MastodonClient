## v2.0.1の変更と確認記録

以下は`v2.0.0`からの変更。配布APKは公開ページに添付済み。

### 今回の変更内容

- 通知一覧：新着件数、既読とみなす条件、新着行の背景表示を揃えた。更新時の自動スクロールを廃止し、新着0件の表示もなくした。新着件数はフィルター行の下へ移動し、ホームと通知の上部表示を薄く読みやすくした。
- 投稿・通知の表示：返信矢印、お気に入りの星、通知種類の塗りつぶしアイコンと黄色の星、リアクション通知の絵文字表示を調整した。投稿下部の件数とアイコンの間隔を整え、件数の文字は従来の書体・サイズを維持した。
- アカウント一覧：お気に入り・ブースト・リアクションの一覧ダイアログに共通の高さ上限と固定タイトルを適用した。最低高さは1件分。読み込み中表示をなくし、名前を先に表示してアバターを非同期で読み込む。画像取得失敗時は代替アイコンを表示する。
- 通知設定：「通知を受け取る方法」にストリーミングの状態と通信設定への案内、アカウント別Push、定期確認通知をまとめ、「Android通知の表示」に起動中のAndroid通知を置いた。定期確認が前景で動いた場合もこの表示設定に従う。
- OS通知からの遷移：通知をタップすると対象アカウントへ切り替え、通知タブの「すべて」を開いて一覧の先頭を更新する。アカウント復元・切替の完了を待って遷移し、通知タブからタイムラインへ戻ってしまう問題を修正した。旧版で作られた通知は受信先アカウントを特定できないため、現在のアカウントで開く。

詳細な表示・設定仕様は[UI・機能仕様](ui-guidelines.md)を参照する。

### リリース時の確認記録と未確認事項

- 通知の既読条件と画面表示の関連テストを更新し、Android単体テスト143件が成功。アイコン・件数調整後のエミュレーター表示を利用者が確認した。
- Fedibirdの`emoji_reaction`通知のアカウントIDと、対象投稿の`emoji_reactions[].account_ids`の一致を利用者が確認した。アカウント一覧ダイアログの変更と通知設定の文面も利用者が了承した。
- 通知設定・定期確認・共通配信の関連単体テスト5件が成功。OS通知タップの修正後はDebug単体テスト145件、アカウント切替競合テスト、Debugビルド、エミュレーター上の通知Intent・通知表示・Push通知テストが成功した。OS通知タップ後に通知タブが維持されることは利用者が実機で確認した。
- 自動の画面遷移テストはエミュレーターにログイン状態がなく、テスト用アカウントでも待機して完走しなかった。テスト用アカウントは削除を確認済み。
- 2026-09-25に配布候補でAndroid単体テスト146件が成功（失敗・エラー・スキップなし）。署名付きReleaseビルドも成功。
- 配布APK内のversionNameは`2.0.1`、versionCodeは`7`。APK Signature Scheme v2で署名検証済み。署名証明書は2.0.0と同じ。SHA-256: `fed3fb797a9f11bdc810b3a9ef94ce84c205960b02fc8c39ea97a175d0ebcc20`。

## v2.0.2リリース候補

比較元は`v2.0.1`。版番号は`2.0.2`（versionCode `8`、未公開）。公開日は未定。
以下は現在の作業ツリーの変更であり、配布対象はリリース前に差分で確定する。

- 画像ビューア：下スワイプ中に背景をフェードし、画像タップで操作UIと上下のシステムバーを切り替える。Android 11以降はタップ時のシステムバーをフェードなしで切り替える。
- 閲覧注意メディア：再び隠す操作をビューアから投稿内へ移す。
- 投稿画面：メディアを閲覧注意にするスイッチを追加し、内容警告の文がある場合は自動で閲覧注意として送信する。
- 投稿画面：CW入力欄と添付タイルをコンパクトにし、添付メディアを本文の下、閲覧注意スイッチを画像の下へ移す。公開範囲の操作は従来の配置を維持する。
- 画像タップ時の操作UIとシステムバーの切り替えは、利用者が実機で問題ないことを確認した。
- 投稿画面のCW・本文・添付メディア・閲覧注意スイッチの配置は、利用者が実機で問題ないことを確認した。
- 通知用の小アイコン：幽霊に見える輪郭を見直し、耳と下向きの鼻が分かる横向きのゾウへ変更した。利用者が比較案から横向きを選択した。Android SDK 37のaapt2でリソースのコンパイルを確認済み。
- タイムライン：位置保持設定がオンの場合、長時間のバックグラウンド中にOSがアプリを終了しても、タスクが残る復帰では前回の投稿付近へ戻す。復元後は「最新へ」で最新の投稿へ移れる。履歴からタスクを閉じた後の起動は対象外。

## リリース用pushの手順

1. GitHub ReleasesとGitタグを確認し、比較元の公開版を確定する。
2. 比較元から配布候補までの差分で対象版の変更内容を更新する。過去の計画や今回含まれない変更を引き継がない。
3. versionNameとversionCodeを確定し、関連文書の版番号を揃える。
4. 配布候補で必要なテスト、ビルド、端末確認を行い、実行した結果と未確認事項を記録する。
5. 署名済みAPKの署名、APK内の版番号、SHA-256を確認する。
6. リリースノートを今回の差分と検証結果から作り、既知の制約を明記する。
7. `git diff --check`と`git status`でコミット対象を確認する。IDE設定、署名鍵、パスワード、認証情報、生成APKをコミットしない。
8. コードと更新済み計画書をコミットし、注釈付きタグを作成する。ブランチ、タグの順にpushする。
9. GitHub Releaseの公開区分、本文、添付APKを確認して公開する。

同名タグがリモートにある場合は、公開済みReleaseへの影響を確認してから版番号またはタグの扱いを決める。
