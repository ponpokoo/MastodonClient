### 実装内容

- 前景中はMastodon Streaming APIで通知を受信し、通知欄と未読数へ即時反映する。
  バックグラウンドでは約15分ごとに簡易取得し、即時通知は保証しない。
- 通知タブ表示時とアプリ復帰時に自動更新する。自動更新とStreaming受信が競合した場合は、
  ID単位で統合して通知の重複と消失を防ぐ。通知元ユーザーの画像も表示する。
- Android共有メニューからテキスト／URLと画像を受け取り、投稿画面の入力・添付へ反映する。
- お気に入り・ブーストは操作直後にアイコンと件数を更新し、API失敗時は操作前の状態へ戻して
  エラーを表示する。同一投稿の通信中操作を抑止し、タイムライン、検索、通知、プロフィール、
  詳細、ハッシュタグ、お気に入り・ブックマーク一覧へ状態を同期する。
- お気に入り数が1件以上の投稿では、お気に入りアイコンの長押しでアカウント一覧を開く。
  一覧から選んだアカウントはプロフィール画面へ移動する。

### リアルタイム通知の方式

- 前景中はアカウントごとにMastodon Streaming APIのユーザーストリームを1本接続し、
  `notification` イベントを通知欄と未読数に即時反映する。同じ接続をタイムライン更新にも使う。
- 接続先はインスタンス情報の `configuration.urls.streaming` を優先し、なければインスタンスURLを使う。
- 異常終了とサーバー側の正常EOFのどちらでも、前景中は最大30秒間隔で再接続する。
- 初期設定ではバックグラウンド移行時に接続を停止する。バックグラウンドのOS通知は
  JobSchedulerによる約15分ごとの簡易取得とし、即時到着は保証しない。
- 常時接続のフォアグラウンドサービスは、電池消費と常駐通知を避けるため採用しない。
  バックグラウンド即時通知はMastodon Web PushとAndroid向け中継サービスを将来候補とする。

調査根拠: [Mastodon Streaming API](https://docs.joinmastodon.org/methods/streaming/)、
[Mastodon Push API](https://docs.joinmastodon.org/methods/push/)、
[Android バックグラウンド実行の概要](https://developer.android.com/develop/background-work/background-tasks)

## 今回の追加変更：設定・プロフィール・デザイン

### 設定

- 設定をカテゴリ一覧と詳細画面の2階層に整理。
- 「ストレージ」に画像キャッシュ削除を追加。アカウント・設定・下書きは保持する。
- 「このアプリについて」にバージョン名とビルド番号を表示。
- 投稿・タイムラインの操作順設定にアイコンを表示し、上下ボタンをドラッグハンドルへ変更。
- 並び替えは指を離したときに保存。読み上げのカスタム操作からも上下に移動できる。

### プロフィール

- ユーザーID直下に投稿・フォロー・フォロワー・登録日を一列で配置。
- プロフィール項目を見出しなしの欄にまとめ、区切り線で整理。確認済みリンクは右端のチェックで表示。
- 「フォローされています」はID横に収まる場合はID横、収まらない場合は表示名横へ配置。
- 三点メニューのポップアップをボタン自体を基準に表示。
- プロフィール画像と三点ボタンの配置は従来の位置を維持。

### デザイン

- ダーク背景をわずかに紫がかったグレーへ変更し、アクセントを淡い青・青灰色へ調整。
- 背景、一覧、下部ナビゲーション、メニュー・ダイアログに控えめな明度差を設定。
- ライトテーマは維持。

### 同じ作業ツリー内の追加改善

- 返信先を判別できる投稿に返信先アカウントを表示し、プロフィールへの導線を追加。
- 通知の自動更新と手動更新のインジケーターを分離。通知タブ表示時・復帰時の更新後に先頭へ移動。
