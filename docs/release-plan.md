## v2.0.2の変更と確認記録

以下は`v2.0.1`からの変更。配布APKは公開ページに添付済み。

### 今回の変更内容

- 画像ビューア：下スワイプ中に背景をフェードし、画像タップで操作UIと上下のシステムバーを切り替える。Android 11以降はタップ時のシステムバーをフェードなしで切り替える。
- 閲覧注意メディア：再び隠す操作をビューアから投稿内へ移す。
- 投稿画面：メディアを閲覧注意にするスイッチを追加し、内容警告の文がある場合は自動で閲覧注意として送信する。
- 投稿画面：CW入力欄と添付タイルをコンパクトにし、添付メディアを本文の下、閲覧注意スイッチを画像の下へ移す。公開範囲の操作は従来の配置を維持する。
- 画像タップ時の操作UIとシステムバーの切り替えは、利用者が実機で問題ないことを確認した。
- 投稿画面のCW・本文・添付メディア・閲覧注意スイッチの配置は、利用者が実機で問題ないことを確認した。
- 通知用の小アイコン：幽霊に見える輪郭を見直し、耳と下向きの鼻が分かる横向きのゾウへ変更した。利用者が比較案から横向きを選択した。Android SDK 37のaapt2でリソースのコンパイルを確認済み。
- タイムライン：位置保持設定がオンの場合、長時間のバックグラウンド中にOSがアプリを終了しても、タスクが残る復帰では前回の投稿付近へ戻す。復元後は「最新へ」で最新の投稿へ移れる。履歴からタスクを閉じた後の起動は対象外。

### リリース時の確認記録

- タイムラインの保存位置からの復元、「最新へ」、別アカウントへ保存位置を引き継がないことの回帰テストを追加した。
- 2026-09-26にDebug単体テスト148件が成功（失敗・エラー・スキップなし）。署名付きReleaseビルドも成功。
- 配布APKはapplication ID `io.github.ponpokoo.mastodonclient`、versionName `2.0.2`、versionCode `8`。APK Signature Scheme v2による署名を検証し、公開ページの添付APKのSHA-256が`1dfdee06ba2c5d13888e201ae99a8abbbf47b17c4d1ec45d75890895af8dde3a`と一致した。
- 投稿詳細から戻るとタイムラインが先頭へ移動する問題を`1d19a0d`で修正し、端末回帰テスト1件が成功。修正版APKはversionName `2.0.2`、versionCode `8`、APK Signature Scheme v2で署名済み。
- 長時間バックグラウンド後のタイムライン復元と、投稿時の閲覧注意フラグの送信結果は利用者が実機で確認した。
- 通知欄の小アイコンは、利用者が実機で表示を確認した。

## v2.1.0リリース準備

比較元は公開版`v2.0.2`。次回の目標版は`2.1.0`（versionCode `9`、未公開）。
公開済み2.0.2の差し替えAPKに含まれる投稿詳細からの復帰修正は、今回の新規変更に含めない。

### 今回の変更内容（配布候補）

- 投稿メディア：添付後にメディアを1件ずつ先行アップロードし、送信率、サーバー処理中、ALT反映中の状態を添付タイルに表示する。投稿時はアップロードと最新ALTの反映完了を待つ。
- 投稿メディア：失敗した添付ごとに再試行とエラー詳細を表示する。サーバー処理の待機が長引いた場合はメディアIDを保持して再確認し、重複アップロードを避ける。下書きにもメディアIDを保存し、復元時に有効性を確認する。
- タイムライン：自分の投稿やブーストを新着件数に含めない。ブースト済みのアイコンを太くし、選択状態を分かりやすくする。
- Android通知：通知をタップして対象アカウントを開いた後、そのアカウントのAndroid通知をまとめて消す。他のアカウントの通知は残す。

### 確認状況

- メディア処理、タイムライン、Android通知の回帰テストを追加した。2026-09-29にDebug単体テスト163件が成功（失敗・エラー・スキップなし）。
- 2.1.0の署名付きReleaseビルドが成功。APKはapplication ID `io.github.ponpokoo.mastodonclient`、versionName `2.1.0`、versionCode `9`。APK Signature Scheme v2で署名を検証した。SHA-256: `ec2376f1ecbdd884809a9df3655938ad0e1cfea251003950c8b0ab30d1981c3b`。
- 2.1.0の変更内容は、利用者が実機確認を完了したと報告した。
- 変更一覧は公開版2.0.2から今回の配布候補までの差分を基にしたもの。GitHub Release公開前にタグと添付APKの対応を最終確認する。

## 次回以降の候補

以下は現時点で2.1.0の変更一覧に含めていない候補。採用時に仕様と優先順位を決める。
UI・機能仕様に記録した改善事項も含め、範囲を決めるときの候補として整理する。

### 機能候補

| --- | --- | --- |

採用項目が決まったら、比較元の公開版と版番号を確定し、この節から次回版の変更内容へ移す。

## リリース用pushの手順

1. GitHub ReleasesとGitタグを確認し、比較元の公開版を確定する。
2. 比較元から配布候補までの差分で対象版の変更内容を更新する。過去の計画や今回含まれない変更を引き継がない。
3. versionNameとversionCodeを確定し、関連文書の版番号を揃える。
4. 配布候補で必要なテスト、ビルド、端末確認を行い、実行した結果と未確認事項を記録する。
5. 署名済みAPKの署名、APK内の版番号、SHA-256を確認する。
6. リリースノートを今回の差分と検証結果から作り、既知の制約を明記する。
7. `git diff --check`と`git status`でコミット対象を確認する。IDE設定、署名鍵、パスワード、認証情報、生成APKをコミットしない。
8. コードと更新済み計画書をコミットし、注釈付きタグを作成する。ブランチ、タグの順にpushする。
9. GitHub Releaseの公開区分、本文、添付APKを確認して公開する。

同名タグがリモートにある場合は、公開済みReleaseへの影響を確認してから版番号またはタグの扱いを決める。
