# 音声添付の調査・修正記録

2026-10-03の作業ツリーで確認。実際に問題が出た投稿のAPIレスポンスは取得していない。
コードの追跡、模擬APIレスポンス、Android 17エミュレーターのローカル音源で確認した。
公開済みAPKや特定インスタンスでの実機確認とは区別する。

## 2.3.0リリース時の実機確認

2026-10-03にユーザーから、今回の未確認項目は実機確認済みとの報告を受けた。
実投稿のHTTPS配信、スピーカーでの可聴確認、最終UIの表示・操作、横画面の音量操作と切り欠き対応を確認済みとして記録する。
以下の「未確認」「未実施」は各調整・自動テスト時点の履歴であり、今回のユーザー報告と区別する。
この報告はすべての端末・コーデックへの対応を保証するものではない。
現行版の配布候補と確認結果は[更新・リリース計画](release-plan.md)を参照する。

## 原因と追跡経路

| 段階 | 修正前の確認結果 |
| --- | --- |
| Mastodon API | 公式仕様は`audio`を添付種別として定義。`url`は本体、`preview_url`はプレビュー画像。模擬レスポンスで両URLが異なるケースとプレビューなしを確認 |
| API DTO | `data/remote/dto/StatusDto.kt`の`MediaAttachmentDto.type: String`が`audio`を保持。`url`と`previewUrl`も別々に保持 |
| Domain Model | `domain/model/TimelineStatus.kt`の`MediaAttachment.type: String`が`audio`を表現できる。音声専用の型追加は不要 |
| Mapper | `data/repository/DefaultTimelineRepository.kt`の`StatusDto.toDomain()`は`type = it.type`、`url = it.url`、`previewUrl = it.previewUrl`をそのまま渡す。音声の除外なし |
| Timeline ViewModel | Repositoryの`TimelineStatus`を一覧状態へ保持。メディア種別によるフィルタや変換なし |
| Compose UI | `HomeTimelineScreen.kt`の`MediaGrid`は動画・GIF動画だけを再生分岐へ送り、音声は`AsyncImage`へ進んでいた。`MediaViewerScreen.kt`も動画以外を`ZoomableImage`へ送っていた |
| Player | 動画は既存の`VideoView`を使用。音声プレイヤーもMedia3依存関係も未導入だった |

`audio`の値がDTOやMapperで消えた問題ではない。UIの種別分岐と音声再生処理が欠落していた。
タイムラインでは音声のプレビュー画像を表示し、本体しかない場合は音声URLを画像として読み込むため、
MP3・WAVの両方が再生操作へ到達できなかった。

## 修正内容

- `MediaGrid`に音声分岐を追加。画像・動画の行配置を維持し、音声は投稿内の全幅操作UIとして添付順に表示する。
- `feature/media/AudioPlayer.kt`を追加。MP3・WAV共通のCompose UIとMedia3 ExoPlayerを使用する。
- `MediaViewerScreen`にも音声分岐を追加し、選択中の音声ページだけを再生可能にする。
- Version Catalogとアプリ依存関係へ`androidx.media3:media3-exoplayer:1.11.1`を追加。
- DTO・Domain Model・Mapper・ViewModelの本番処理は変更しない。

```text
MediaAttachment.type == audio
    → 共通AudioPlayer
    → MediaItem.fromUri(attachment.url)
    → Media3 / ExoPlayer
```

URL拡張子・MIME Typeで表示や再生可否を分岐しない。`preview_url`への代替は行わない。
本体URLがnull・空の場合は操作を無効化して理由を表示する。

プレイヤーは初回の再生操作で生成し、再生・一時停止・終了・読み込み・エラーをUIに反映する。
終了後の再生操作は先頭へ戻す。失敗時は再試行できる。
メインスレッド上の共有MediaPlaybackOwnerが、別の音声・全画面動画を選択した際に前のプレイヤーを一時停止する。
読み込み中のプレイヤーも競合対象とする。OSの音声フォーカスとイヤホン取り外し時の停止を有効にする。
画面外への移動、背景移行、ビューアのページ変更では一時停止し、自動復帰しない。
Composeからの破棄・URL変更ではリスナーを除去して`release()`する。

## シーク・音量・動画操作の追加

同日の追加変更で、音声と全画面動画・GIF動画の再生状態を`MediaPlayback.kt`へ、
操作UIを`MediaPlaybackControls.kt`へ共通化した。全画面動画は`VideoPlayer.kt`の
Media3 ExoPlayerとSurfaceViewで表示する。投稿内の無音動画・GIF動画は既存のVideoViewを維持する。

- ドラッグできるシークバーと5秒戻る・10秒進むを追加。ドラッグ中は位置をプレビューし、指を離した時にシークする。
- 一時停止中のシークは再生を始めず、位置だけを変更する。送り戻しの位置は先頭・末尾に制限する。
- 本体の長さとMedia3のシーク対応を確認して操作を有効化する。長さ不明・非対応・エラー時は無効化する。
- CBRのMP3など、シーク表がない音源ではMedia3の定ビットレートシークを有効にする。この場合は近似シークになる。
- 一時停止中に末尾へ送った場合、次の再生操作では先頭へ戻す。プレイヤーが返す末尾位置の丸めに依存せず、操作時の到達を保持する。
- プレイヤーの音量を0～100%で調整し、ミュート解除で直前の値に戻す。生成前の音量変更も初回生成時に適用する。
- 端末のメディア音量は変更しない。音量値はプレイヤーの破棄後に保存しない。
- 動画は初回表示時に再生し、非選択ページでは再生しない。ページ変更・背景移行では一時停止し、戻っても自動再開しない。
- 音声と全画面動画の再生競合を共有MediaPlaybackOwnerで防ぐ。GIF動画の全画面ループも維持する。
- 音声・動画とも`attachment.url`だけを再生元に使用する。

## 音声プレイヤーの表示変更

構成案の確定後、音声だけを変更した。動画の秒送りを画面タップで一時表示する案は今回は見送った。
動画のシークバー・操作ボタン・音量スライダーは、それ以前の実装を維持する。

- 投稿者の丸いアイコンに再生・一時停止を重ね、左右に5秒戻る・10秒進むを配置。数字は円形矢印の中央。
- 背景は読み込んだアイコンを32×32へ縮小して平均色を求め、明るさを抑えて生成する。計算は背景処理で行い、URL変更・破棄でキャンセルする。
- 欠落・読み込み失敗・透明画像では人物アイコンまたは中立の背景を使い、音声本体の再生には影響させない。
- シークバーは調整済み構成案の5pxをAndroidの5 dpへ反映。線を太くしても48 dpの操作領域を維持する。
- 右下の音量ボタンから上へ縦スライダーを開く。上向きドラッグで音量が増え、ミュート解除で元の値へ戻す。
- 外側タップと戻る操作で音量バーを閉じる。画面上端では表示可能な高さに合わせて短くし、背景移行・非選択時にも閉じる。
- `MediaAttachment.authorAvatarUrl`には音声の投稿者情報を補足し、単独のビューアまで保持する。過去のキャッシュでは一覧の投稿者情報で補う。再生元は引き続き`attachment.url`。
- `AudioPlayer.kt`と`AudioPlayerControls.kt`が音声の表示を担当。再生・終了・音量・シークは既存`MediaPlayback.kt`を共用する。

## カードの高さと下部の配置の修正

追加調整後のスクリーンショットで、バーが投稿者アイコンのすぐ下に残っていることを確認した。
`heightIn(min = 220.dp).aspectRatio(1.67f)`の組み合わせでは、幅÷1.67が最低高さより小さいと
内部のレイアウトが外枠より低くなり、上下に余白を残して中央に置かれる。
この余白と下部の操作行の高さがあるため、前回の線だけの移動では調整が不十分だった。

カードの高さを幅÷1.67と最低220 dpから明示的に求め、外枠と内部の高さを合わせた。
下部8 dpの追加余白をなくし、線とつまみを48 dpの操作領域内で18 dp下げた。
投稿者アイコンのサイズは変更せず、シークバーと時間・音量の行をカード下端を基準に配置する。
この表示調整でもテストは実行していない。本体のKotlinコンパイルと差分確認は成功した。
変更後の端末表示は未確認。
