# UI・機能仕様

現在の実装を基準とする仕様。開発構成と確認手順は [開発ガイド](project-setup.md) にまとめる。
未実装の構想は末尾に分け、実装済みの機能として扱わない。
作業ツリーの対象版は`2.0.2`（versionCode 8、未公開）。公開・確認状況は [更新・リリース計画](release-plan.md)、
変更範囲に応じたテスト方針は [開発ガイド](project-setup.md#ビルドと確認) を参照する。

## デザイン方針

**Mastodon公式アプリの情報構造と基本操作に準拠しつつ、このアプリ独自のデザインと使いやすさを出す。**
公式アプリは画面階層、投稿の読み順、一般的な操作の参考とする。余白、アイコンの配置、
詳細画面、ダイアログ、表示のカスタマイズは本アプリの利用感に合わせて設計する。
公式アプリとの見た目の一致そのものを完成条件にはしない。

- Jetpack Compose / Material 3を使用し、本文を主役にする。投稿は薄い区切り線で連続させる。
- ライトは既存の中立色と紫系アクセント、ダークはわずかに紫を含むグレーと低彩度の青・青灰色を基本とする。ライト・ダーク・システム設定に対応する。
- 公式のイラストなどのアセットは流用せず、標準アイコンと独自の実装を使う。
- スマートフォンを対象とする。タブレット専用の2ペインやナビゲーションレールは対象外。
- アイコンの見た目を小さくしても操作領域は原則48 dp以上とする。システム文字倍率、
  読み上げラベル、色以外での選択状態の表現を考慮する。

ダークテーマの調整基準は背景 #1A1920、メイン一覧の表示面 #1E1E24、下部ナビゲーション #202027。設定のグループ・メニュー・ダイアログはMaterial 3のsurfaceContainer各段階で明度差を付ける。本文は #E7E6EC、補助テキストは #BDBDC9、主要アクセントは淡い青 #B5C9E2 とする。色は実機確認後に調整する暫定値。

## 画面構成

メイン画面はホーム・検索・通知・プロフィールの4タブ。
ホームから閲覧アカウント、ホーム／ローカル／連合タイムラインを切り替え、
お知らせ、設定、投稿画面へ進む。リストと保存済み投稿は別画面で表示する。

検索はアカウント・投稿・ハッシュタグの結果を表示する。通知は「すべて」「メンション」
「リアクション」で絞り込む。タブ間で投稿の表示部品を共用し、読み込み・空・エラー・再試行を扱う。

メインタブは下部ナビゲーションで切り替え、横スワイプでは移動しない。通知の
「すべて」「メンション」「リアクション」はタブ選択と左右スワイプの両方で切り替える。
Androidのステータスバーはシステム操作領域のため、画面上部のタイトルをタップすると
現在表示中の一覧を先頭までスクロールする。ホームのフィード切り替えはタイトル右の
下向きアイコンから行う。
ホーム、通知、プロフィール、ハッシュタグ一覧の引っ張って更新は、56 dpの操作距離で発火する。
更新インジケーターの表示上の移動距離は48 dpに抑え、発火距離とは別に扱う。

閲覧アカウントを切り替えるとメイン画面のデータとストリームを切り替える。
投稿画面の投稿元選択は閲覧アカウントを変更しない。

通常の画面遷移は220msの横スライドを使用する。進むときは遷移先だけを左方向へ、
戻るときは手前の画面だけを右方向へ動かし、背後の画面は固定する。
文字の重なりを避けるためフェード・拡大縮小は併用せず、各画面の不透明な背景で覆う。
投稿画面とメディアビューアは別のダイアログ表示として扱う。

ホームのStreaming新着は、一覧の先頭を表示している場合は先頭を維持して自動表示し、上部に「新着○件」を約1.8秒表示する。途中を読んでいる場合は閲覧位置を維持し、未確認の新着件数を上部に表示し続ける。件数表示のタップで先頭へ移動し、手動で先頭へ戻った場合も件数を解除する。別タブ・別画面の閲覧中は自動スクロールしない。
「引っ張って更新時に元の場所にとどまる」がオンなら、長時間のバックグラウンド中にOSがアプリを終了しても、タスクが残っている復帰では表示中の投稿付近を再取得して位置を戻す。復元した範囲では上部の「最新へ」から新着側へ移動できる。履歴からタスクを閉じた後の起動は対象外とし、設定がオフなら最新の投稿から読み込む。
手動更新とStreamingの新着表示は、同じ濃い青灰色の薄い丸背景・明るい中太文字・上部配置を使用する。手動更新で0件の場合は通知を表示しない。新着件数はタイムラインIDで重複を除き、投稿編集は加算しない。削除とアカウント・フィード切替では対応する未確認件数を解除する。HTTP更新中に受け取ったStreaming新着は更新レスポンスと統合して保持する。

## 投稿一覧と詳細

`StatusCard` はドメインモデルと表示設定を受け取る共通部品。
投稿者、ブースト元、HTML本文、CW、リンクカード、メディア、ALT、対応サーバーの
絵文字リアクションを表示する。CWやセンシティブメディアは表示操作で開く。
画像・動画は全画面ビューアへ進み、画像の拡大と動画の再生操作に対応する。
投稿画面でメディアを添付すると「メディアを閲覧注意にする」スイッチを表示する。
内容警告の文がある場合はメディアも自動的に閲覧注意とし、スイッチはオンのまま操作不可にする。
投稿画面ではCW、本文、添付メディア、閲覧注意スイッチの順に置く。
詳細画面でも引っ張って再取得できる。投稿の三点メニューから、HTML装飾を除いた本文をコピーできる。
返信先がメンション情報または投稿者情報から判別できる場合は「返信先: @アカウント名」を表示し、
プロフィールへ移動できる。返信先を判別できない投稿にはこの表示を付けない。
画像ビューアは下方向のドラッグに合わせて背後を見せ、一定距離で閉じる。画像のタップで
操作UIとステータスバー・ナビゲーションバーの表示を切り替える。Android 11以降では
システムバーの標準フェードを使わず、操作UIと同じ描画で切り替える。拡大画像の移動は表示範囲内に制限し、
ピンチで1倍未満に縮めた画像は指を離すと1倍に戻す。閲覧注意メディアの再非表示は
投稿内の「閲覧注意に戻す」で操作する。

| 項目 | 現在のレイアウト |
| --- | --- |
| 投稿外側の余白 | 左8 dp、右16 dp、上12 dp、下2 dp |
| プロフィール画像 | 小40／標準44／大56 dp |
| 投稿者情報 | 表示名とアカウント名の2段 |
| 相対時刻と公開範囲 | 右側に配置し、三点メニューと同じ48 dp領域の縦中央に揃える |
| 一覧の本文開始位置 | 左余白＋画像幅＋8 dp（標準時は画面左から60 dp） |
| 一覧の本文と操作列 | 間隔12 dp |
| 詳細の本文・メディア | 左右16 dp、画像列に合わせた字下げなし |
| 詳細の操作列 | 本文・メディアの8 dp下。その8 dp下に補助情報 |
| 詳細の補助情報 | 日時・クライアント名はbodyMedium、反応件数はbodyLarge |

詳細本文の文字サイズと行間もタイムライン設定に従う。詳細専用の文字サイズ設定はない。
日時は折り返し、件数リンクは幅に応じて次の行へ送る。

お気に入りとブーストはOptimistic UI Updateを使用する。操作直後にアイコンと件数を更新し、
通信成功時はサーバー応答で確定する。失敗時は操作前の状態へ戻し、Snackbarでエラーを表示する。
同一投稿の通信完了までは追加のお気に入り・ブースト操作を受け付けない。状態変更はタイムライン、
検索、通知、プロフィール、投稿詳細、ハッシュタグ、お気に入り・ブックマーク一覧で共有する。
投稿下部の返信は矢印、お気に入りは未選択で輪郭の星・選択中は塗りつぶしの星を使う。
返信・ブースト・お気に入りの件数は従来のlabelSmallでアイコンから4 dpの位置に表示し、数字を含む操作領域を48 dp以上に保つ。
0件は表示せず、大きな件数はK・M表記にする。
お気に入り数が1件以上の投稿では、いいねアイコンの長押しで「お気に入りしたアカウント」一覧を開く。
通常タップはいいね／解除のままとし、長押しでは状態を変更しない。一覧のアカウントを選ぶとプロフィールへ移動する。

投稿の三点メニューは中央のダイアログ。各項目はアイコンと左揃えの本文で統一し、対象者名はタイトルにまとめる。
通常操作とアカウント操作（自分の投稿では削除）を区切り線で分ける。
項目数が多いときは内部をスクロールする。
お気に入り・ブースト・リアクションのアカウント一覧は共通の中央ダイアログを使う。
高さは1件分（129 dp）を最小とし、最大で画面の80%とする。タイトルと閉じるボタンを固定し、一覧だけをスクロールする。
一覧とアバターの読み込み中は進行表示を出さない。アカウント情報を受け取ったら名前を先に描画し、次の描画後に表示行のアバターを非同期で読み込む。画像の取得失敗時・URLが空の場合だけ代替アイコンを表示する。
**各件数が0の場合はそのリンクを無効化し、一覧ダイアログを開かない。**
アカウント選択、お知らせなどの他の表示まで中央ダイアログに統一したわけではない。

## 設定と初期値

`SettingsScreen` はカテゴリ一覧から詳細へ進む2階層構成とする。外観、タイムライン表示、メディア、タイムラインと通信、通知、投稿、アカウント管理、ストレージ、このアプリについてを表示する。詳細から戻るとカテゴリ一覧へ戻り、一覧から戻ると元の画面へ戻る。設定はDataStoreへ保存し、表示へ反映する。
アカウント別の設定キーはローカルのセッションID。その他はアプリ全体に適用する。

ストレージでは画像キャッシュの削除を確認ダイアログから実行する。対象はCoilのメモリ・ディスクキャッシュのみで、アカウント、設定、下書き、編集中の添付は保持する。削除中は再実行を抑止し、成功・失敗を表示する。表示中・通信中の画像によってキャッシュは再作成される場合がある。投稿データのメモリキャッシュやWebブラウザーのデータは対象外とする。
このアプリについてでは、インストール済みAPKのversionNameとversionCodeを表示する。

投稿とタイムラインの操作順設定は、各操作のアイコンと名称、右端のドラッグハンドルを表示する。ハンドルを上下にドラッグして離すと順序を保存する。読み上げのカスタム操作からも上下へ移動できる。タイムラインの表示・非表示チェックは独立して維持する。
タイムライン表示にはサンプル投稿のプレビューと表示設定の初期化がある。
リアクション操作はサーバー対応時に表示する。
GIF設定は投稿メディアのgifv再生で使用し、プロフィール画像やカスタム絵文字のアニメーションを
個別に切り替える設定ではない。Dynamic Colorの設定はない。

定期確認通知は登録済みアカウントをJobSchedulerで確認する方式で、プッシュ通知ではない。
OSの通知許可と実行制約に従うため、15分ちょうどの到着は保証しない。
前景中はStreaming APIのユーザーストリームで通知を即時反映し、切断時は再接続する。「起動中のAndroid通知」がオンならAndroid通知にも表示する。対象は閲覧中アカウントで、ストリーミング設定とOSの通知許可に従う。Pushはストリーミングと独立して受信し、前景でのAndroid通知表示は同じ設定に従う。定期確認が前景で動いた場合も同設定に従い、オフならAndroid通知を表示せずに確認済み位置を進める。受信時点で配信対象だったAndroid通知は本文を先に表示し、取得できたプロフィール画像を同じ通知へ後から追加する。詳細・設定画面を開いている間もActivityが前景なら接続を維持する。定期確認・Pushと配信履歴を共有し、各アカウント直近500件の通知IDで重複を抑止する。通知チャンネルは既存の「Mastodonの新着通知」を使用し、音・バナーはOS設定に従う。OS通知タップでは対象アカウントの通知タブ「すべて」を開き、一覧を更新して先頭を表示する。Relay／FCMの実配信は未接続。

設定 → 通知は「通知を受け取る方法」にストリーミングの状態と通信設定への案内、アカウント別Push、定期確認通知を並べ、「Android通知の表示」に起動中のAndroid通知を置く。後者は受信手段ではなくOS通知の表示だけを制御する。
現在は外部通知サービスが未設定のため「準備中」となり、有効化できない。
接続後は必要に応じて通知許可・再認証を求める。解除失敗は解除待ちとして保存し、
起動・前景復帰時や再試行ボタンから再開する。詳細は[通知設定と購読管理](push-settings.md)を参照。
初期設定ではバックグラウンドでストリームを停止するため、バックグラウンドでの即時到着は保証しない。
ストリーミングのWi-Fi条件は接続開始時に判定する。
通知内の投稿引用はメディア付きなら添付件数を表示する。件数の位置は本文の下のまま、
文字はlabelMediumとする。返信系の通知だけは投稿カードと操作列を表示し、
独立した返信ボタンや通知者と投稿者の重複したプロフィール画像を表示しない。
その他の通知は引用形式を維持する。
通知一覧の種類アイコンは塗りつぶし型に揃え、お気に入りの星は黄色にする。絵文字リアクション通知では、通知したアカウントIDと投稿のリアクション別`account_ids`が1種類だけ一致するとき、その絵文字を表示する。カスタム絵文字は画像URLを使用し、一致しない・複数に一致する・画像の取得に失敗する場合は汎用の塗りつぶしアイコンを表示する。
Androidのシステム通知はステータスバー用の単色の象アイコンに加え、取得できる場合は通知元ユーザーのプロフィール画像を大アイコンに表示する。
通知タブを開いたときと、通知タブを表示したままアプリが前景に戻ったときは、最新の通知を自動取得する。
自動取得中にStreaming APIから受け取った通知もIDで統合し、重複表示や上書き消失を防ぐ。
手動・自動更新とStreaming受信では通知一覧を自動スクロールしない。新着がある場合は「すべて／メンション／リアクション」のフィルター行の下に、ホームと同じ「新着○件」を表示し、タップで「すべて」の先頭へ移動する。先頭に新着が表示されたら既読にしてベルの件数を消し、短時間だけ件数表示を残す。途中を閲覧中は位置と件数表示を保つ。取得失敗時は既読にしない。新着が0件の場合は件数表示を出さない。通知IDで重複を除く。
新着通知の行は背景色を変えて示す。既読になっても、次の更新成功または通知タブを離れるまで背景色を保つ。更新失敗では背景色を消さない。
自動更新では引っ張って更新のインジケーターを出さず、手動更新時だけ表示する。
「すべて」の先頭に最新通知が表示された時点で、そのIDを既読マーカーとして保存する。
通知ごとの既読表現やOS通知から対象詳細への直接遷移は今後の確認・改善対象とする。
通知一覧は初回・追加取得ごとに最大80件を読み込み、末尾到達時により古い通知を追加取得する。
インスタンスが80件未満に制限しても取得を続け、追加取得に失敗した場合は一覧末尾で再試行できる。

## 投稿と下書き

新規投稿・返信・自分の投稿編集に対応する。投稿元、公開範囲、本文、CW、センシティブ指定、
画像・動画添付、ALT編集、投票、カスタム絵文字挿入、メンション候補を扱う。

Androidの共有メニューでテキスト／URLまたは1枚の画像を共有先として受け取る。
ログイン済みなら投稿画面を開き、テキストを本文に、画像を添付に反映する。
未ログインなら共有内容を一時保持し、ログイン完了後に投稿画面を開く。
共有画像は投稿画面でアプリ専用領域へ取り込み、ALT編集と投稿前確認は通常の添付と同じ扱いにする。
文字数や添付上限は投稿元サーバーの設定を取得する。
投票とメディアは併用不可。投票は最大4択、複数選択に対応し、期間の初期値は24時間。
言語や投票期間を選ぶUI、添付の並べ替えUIはない。
メディアはシステムの写真選択UIから選ぶ。投稿画面の添付は本文入力欄の下に
2列のタイルで配置する。サムネイル・ファイル名・サイズ・削除操作を表示し、
ALTは編集ボタンからダイアログで入力する。入力済みALTはタイル内で1行に要約する。
バーのゴミ箱は確認なしで本文のみをクリアし、CW・投票・添付・返信先と保存済み下書きは変更しない。

内蔵ブラウザーはJavaScriptとDOMストレージを有効にする。戻る操作は閲覧履歴があれば
前のページへ戻り、履歴がなければブラウザー画面を閉じる。別ウィンドウを開くページや
一部の外部認証・ダウンロードは個別確認が必要で、全Webサイトとの互換性は保証しない。

投稿中・メディア取り込み中は競合する操作を抑止し、ALT未入力時は設定に応じて確認する。
投稿編集中は投稿元アカウントを切り替えられない。
投稿元を切り替える際は現在の入力をそのアカウントの一時バッファへ保持し、切替先の入力を復元する。

**永続下書きは明示的に保存する。自動保存の設定はない。**
画面を閉じるときの入力保持はメモリ上の一時バッファであり、プロセス終了後の復元を保証しない。
保存済み下書きは投稿元・返信先・編集対象を含むキーで区別し、本文、CW、公開範囲、
センシティブ指定、添付ファイル情報とALT、投票を保存する。添付はアプリ専用領域へ取り込む。
保存済み下書きの呼出・削除に対応し、投稿成功時は対応する下書きとバッファを削除する。
保存済み下書きを呼び出した時点で一覧から除き、内容と添付ファイルを編集中の投稿へ移す。
再び下書きに残すには明示保存が必要。保存済み一覧での長押し削除には確認を出す。

## プロフィール

画像はヘッダー左下に重ね、編集・フォローボタンと三点メニューは右下に配置する。ユーザーID直下に投稿・フォロー・フォロワー・登録日を一列で表示し、その下にフォロー関係と自己紹介を配置する。アカウント名は折り返して表示する。「フォローされています」はIDと一行に収まる場合はID横、収まらない場合は表示名横へ配置する。三点メニューのポップアップはボタン自体を基準として表示する。

プロフィール項目は自己紹介の下に薄い背景の欄でまとめ、項目間を区切り線で分ける。「補足情報」の見出しは表示しない。リンクとカスタム絵文字を維持し、確認済みリンクは項目の右端に小さなチェックのみを表示する（読み上げラベルは「リンク確認済み」）。項目が空なら追加の表示領域を設けない。

ヘッダー、画像、表示名、アカウント名、自己紹介、プロフィール項目と認証済み表示、
登録日、投稿・フォロー・フォロワー数を表示する。固定投稿と「投稿」「投稿と返信」「メディア」の
タブ、追加読み込みに対応する。フォロー数からアカウント一覧を開く。

自分のプロフィールは表示名・自己紹介・画像・ヘッダー・承認制・プロフィール項目を編集する。
他のアカウントではフォロー状態を表示し、フォロー／解除、ミュート、ブロック、理由付き通報を扱う。
ミュート・ブロックの変更は確認ダイアログを使用する。

プロフィール詳細のメニューに共有・コピー・QR・外部ブラウザーがあり、自分の場合はリスト、
お気に入り、ブックマーク、フォロー中タグ、アカウント設定も表示する。
メインのプロフィールタブのメニューとは項目が異なる。
フォロー中タグとアカウント設定はWebリンクであり、専用のネイティブ画面ではない。

## 今後の検討・確認事項

以下は実装済みの保証ではなく、改善候補として管理する。

- 言語・投票期間の指定、添付の並べ替えとサーバー制限への対応強化。
- プロフィール編集のdiscoverable選択（現状は保存時にtrueを渡す）と未保存入力・失敗時の扱い。
- フォロー中タグの専用画面と、現在のWebリンク先の妥当性。
- ネットワーク変更直後のストリーミング制御、データセーバー・動きを減らす設定との連動。
- 非表示にした操作への代替導線、文字拡大時の折り返し、読み上げ・コントラストの実機確認。
- 操作を含むUI解説を用意する。

UI変更時は公式アプリの慣れた操作を保ちつつ、読みやすさ・押しやすさ・独自の表示調整を評価する。
