# UI・機能仕様

この文書は、現在の実装に基づくUI・機能仕様をまとめたものです。対象版は`2.1.1`、versionCodeは`10`です。

開発構成と確認手順は[開発ガイド](project-setup.md)、公開・確認状況は[更新・リリース計画](release-plan.md)を参照してください。
変更範囲に応じたテスト方針は[開発ガイドの「ビルドと確認」](project-setup.md#ビルドと確認)に記載しています。

未実装の構想は、末尾の「今後の検討・確認事項」に分けて記載します。

## デザイン方針

Mastodon公式アプリの情報構造と基本操作を参考に、画面階層、投稿の読み順、一般的な操作を設計する。

余白、アイコンの配置、詳細画面、ダイアログ、表示のカスタマイズは、本アプリの使いやすさを基準に設計する。
完成時の評価では、情報構造と操作性を確認する。公式アプリと見た目を一致させる必要はない。

- Jetpack Compose / Material 3を使用し、本文を読みやすいレイアウトにする。投稿は薄い区切り線で連続させる。
- ライトは既存の中立色と紫系アクセント、ダークはわずかに紫を含むグレーと低彩度の青・青灰色を基本とする。ライト・ダーク・システム設定に対応する。
- 公式のイラストなどのアセットは流用せず、標準アイコンと独自の実装を使う。
- スマートフォンを対象とする。タブレット専用の2ペインやナビゲーションレールは対象外。
- アイコンの見た目を小さくしても操作領域は原則48 dp以上とする。システム文字倍率、
  読み上げラベル、色以外での選択状態の表現を考慮する。

ダークテーマの調整基準は背景 #1A1920、メイン一覧の表示面 #1E1E24、下部ナビゲーション #202027。設定のグループ・メニュー・ダイアログはMaterial 3のsurfaceContainer各段階で明度差を付ける。本文は #E7E6EC、補助テキストは #BDBDC9、主要アクセントは淡い青 #B5C9E2 とする。色は実機確認後に調整する暫定値。

## 画面構成

メイン画面はホーム・検索・通知・プロフィールの4タブ。
ホームから閲覧アカウント、ホーム／ローカル／連合タイムラインを切り替え、
お知らせ、設定、投稿画面へ進む。リストと保存済み投稿は別画面で表示する。

検索はアカウント・投稿・ハッシュタグの結果を表示する。通知は「すべて」「メンション」
「リアクション」で絞り込む。タブ間で投稿の表示部品を共用する。
読み込み中、データがない場合、取得エラーの状態を表示し、再試行に対応する。

メインタブは下部ナビゲーションで切り替え、横スワイプでは移動しない。通知の
「すべて」「メンション」「リアクション」はタブ選択と左右スワイプの両方で切り替える。
Androidのステータスバーはシステム操作領域のため、画面上部のタイトルをタップすると
現在表示中の一覧を先頭までスクロールする。ホームのフィード切り替えはタイトル右の
下向きアイコンから行う。
ホーム、通知、プロフィール、ハッシュタグ一覧での引っ張って更新の発動しきい値は、56 dpを1.5で割った約37.3 dpとする。
更新インジケーターの表示上の移動距離は48 dpを維持し、発動しきい値とは別に扱う。

閲覧アカウントを切り替えるとメイン画面のデータとストリームを切り替える。
投稿画面の投稿元選択は閲覧アカウントを変更しない。

通常の画面遷移は220msの横スライドを使用する。進むときは遷移先だけを左方向へ、
戻るときは手前の画面だけを右方向へ動かし、背後の画面は固定する。
文字の重なりを避けるためフェード・拡大縮小は併用せず、各画面の不透明な背景で覆う。
投稿画面とメディアビューアは別のダイアログ表示として扱う。

ホームでStreamingの新着投稿を受信した場合、一覧の先頭を表示していれば、新着投稿を自動表示して先頭の位置を維持する。
画面上部には「新着○件」を約1.8秒表示する。

一覧の途中を閲覧している場合は、閲覧位置を維持する。未確認の新着件数を画面上部に表示し、件数表示をタップすると先頭へ移動する。
手動で先頭へ戻った場合も件数表示を消す。別タブや別画面の閲覧中は、自動スクロールしない。

「引っ張って更新時に元の場所にとどまる」がオンの場合、OSによるプロセス終了後も、タスクが残っていれば閲覧位置を復元する。
表示していた投稿付近を再取得し、その位置へ戻す。復元後は、画面上部の「最新へ」から新着側へ移動できる。

履歴からタスクを閉じた後の起動では、閲覧位置を復元しない。設定がオフの場合は、最新の投稿から読み込む。

手動更新とStreamingの新着件数は、画面上部に同じデザインで表示する。
背景は濃い青灰色の薄い丸背景、文字は明るい色の中太文字とする。手動更新で新着が0件の場合は、件数表示を出さない。

新着件数はタイムラインIDで重複を除く。投稿の編集と自分の投稿・ブーストは件数に加算しない。
自分の投稿・ブーストは一覧へ反映し、先頭を表示している場合は、件数を表示せずに先頭へ移動する。

投稿の削除やアカウント・フィードの切り替え時には、対応する未確認件数を解除する。
HTTP更新中に受信したStreamingの新着投稿は、更新レスポンスと統合して保持する。

## 投稿一覧と詳細

引っ張って更新の発動しきい値は、56 dpを1.5で割った約37.3 dpとする。更新インジケーターの移動距離は48 dpを維持する。
従来比1.5倍の追従により、発動までに必要な指の移動量は従来の約3分の2になる。操作感はエミュレータで確認して調整する。

投稿一覧の日時は、1年以上前の投稿では年を含む「2025年10月1日」の形式で表示する。1年未満は従来の相対時間・月日表示を使い、判定と日付表示は端末のタイムゾーンに従う。

`StatusCard` はドメインモデルと表示設定を受け取る共通部品。
投稿者、ブースト元、HTML本文、CW、リンクカード、メディア、ALT、対応サーバーの
絵文字リアクションを表示する。CWやセンシティブメディアは表示操作で開く。
画像・動画は全画面ビューアへ進み、画像の拡大と動画の再生操作に対応する。
投稿画面でメディアを添付すると「メディアを閲覧注意にする」スイッチを表示する。
内容警告の文がある場合はメディアも自動的に閲覧注意とし、スイッチはオンのまま操作不可にする。
投稿画面ではCW、本文、添付メディア、閲覧注意スイッチの順に置く。
詳細画面でも引っ張って再取得できる。投稿の三点メニューから、HTML装飾を除いた本文をコピーできる。
会話詳細を開くと、会話の取得後に選択した投稿を画面中央へ配置する。前後の投稿が少ない場合は、スクロール可能な範囲で位置を調整する。
投稿が画面より長い場合は、その投稿の先頭を表示する。

手動スクロールの開始後は、中央への配置を繰り返さない。画面へ戻った場合や、反応の更新・会話の再取得時も、中央へ移動し直さない。

返信先がメンション情報または投稿者情報から判別できる場合は「返信先: @アカウント名」を表示し、
プロフィールへ移動できる。返信先を判別できない投稿にはこの表示を付けない。
画像ビューアは下方向のドラッグに合わせて背後を見せ、一定距離で閉じる。画像のタップで
操作UIとステータスバー・ナビゲーションバーの表示を切り替える。Android 11以降では
システムバーの標準フェードを使わず、操作UIと同じ描画で切り替える。拡大画像の移動は表示範囲内に制限し、
ピンチで1倍未満に縮めた画像は指を離すと1倍に戻す。閲覧注意メディアの再非表示は
投稿内の「閲覧注意に戻す」で操作する。

| 項目 | 現在のレイアウト |
| --- | --- |
| 投稿外側の余白 | 左8 dp、右16 dp、上12 dp、下2 dp |
| プロフィール画像 | 小40／標準44／大56 dp |
| 投稿者情報 | 表示名とアカウント名の2段 |
| 相対時刻と公開範囲 | 右側に配置し、三点メニューと同じ48 dp領域の縦中央に揃える |
| 一覧の本文開始位置 | 左余白＋画像幅＋8 dp（標準時は画面左から60 dp） |
| 一覧の本文と操作列 | 間隔12 dp |
| 詳細の本文・メディア | 左右16 dp、画像列に合わせた字下げなし |
| 詳細の操作列 | 本文・メディアの8 dp下。その8 dp下に補助情報 |
| 詳細の補助情報 | 日時・クライアント名はbodyMedium、反応件数はbodyLarge |

詳細本文の文字サイズと行間もタイムライン設定に従う。詳細専用の文字サイズ設定はない。
日時は折り返し、件数リンクは幅に応じて次の行へ送る。

お気に入りとブーストはOptimistic UI Updateを使用する。操作直後にアイコンと件数を更新し、
通信成功時はサーバー応答で確定する。失敗時は操作前の状態へ戻し、Snackbarでエラーを表示する。
同一投稿の通信完了までは追加のお気に入り・ブースト操作を受け付けない。状態変更はタイムライン、
検索、通知、プロフィール、投稿詳細、ハッシュタグ、お気に入り・ブックマーク一覧で共有する。
投稿下部の返信は矢印、お気に入りは未選択で輪郭の星・選択中は塗りつぶしの星を使う。ブーストは未選択で通常の矢印・選択中は線の太い矢印を使う。
返信・ブースト・お気に入りの件数は従来のlabelSmallでアイコンから4 dpの位置に表示し、数字を含む操作領域を48 dp以上に保つ。
0件は表示せず、大きな件数はK・M表記にする。
お気に入り数が1件以上の投稿では、いいねアイコンの長押しで「お気に入りしたアカウント」一覧を開く。
通常タップはいいね／解除のままとし、長押しでは状態を変更しない。一覧のアカウントを選ぶとプロフィールへ移動する。

投稿の三点メニューは中央のダイアログ。各項目はアイコンと左揃えの本文で統一し、対象者名はタイトルにまとめる。
通常操作とアカウント操作（自分の投稿では削除）を区切り線で分ける。
項目数が多いときは内部をスクロールする。
お気に入り・ブースト・リアクションのアカウント一覧は、共通の中央ダイアログで表示する。
高さは1件分の129 dp以上、画面の80%以下とする。タイトルと閉じるボタンは固定し、一覧だけをスクロールさせる。

一覧とプロフィール画像の読み込み中は、進行表示を出さない。アカウント情報を受信したら、名前を先に表示する。
その次の描画が完了した後、表示中の行のプロフィール画像を非同期で読み込む。

画像の取得に失敗した場合、または画像URLが空の場合に限り、代替アイコンを表示する。
件数が0の場合はリンクを無効にし、一覧ダイアログを開かない。

中央ダイアログの共通仕様は、このアカウント一覧に適用する。アカウント選択やお知らせなどは、各画面の表示仕様に従う。

## 設定と初期値

`SettingsScreen`は、カテゴリ一覧とカテゴリ別の詳細画面からなる2階層構成とする。

カテゴリ一覧には、外観、タイムライン表示、メディア、タイムラインと通信、通知、投稿、アカウント管理、ストレージ、このアプリについてを表示する。

詳細画面で戻る操作を行うと、カテゴリ一覧へ戻る。カテゴリ一覧で戻る操作を行うと、設定を開く前の画面へ戻る。

設定はDataStoreに保存して表示へ反映する。アカウント別の設定は、ローカルのセッションIDをキーに保存する。
その他の設定はアプリ全体に適用する。

ストレージでは画像キャッシュの削除を確認ダイアログから実行する。対象はCoilのメモリ・ディスクキャッシュのみで、アカウント、設定、下書き、編集中の添付は保持する。削除中は再実行を抑止し、成功・失敗を表示する。表示中・通信中の画像によってキャッシュは再作成される場合がある。投稿データのメモリキャッシュやWebブラウザーのデータは対象外とする。
このアプリについてでは、インストール済みAPKのversionNameとversionCodeを表示する。

投稿とタイムラインの操作順設定は、各操作のアイコンと名称、右端のドラッグハンドルを表示する。ハンドルを上下にドラッグして離すと順序を保存する。読み上げのカスタム操作からも上下へ移動できる。タイムラインの表示・非表示チェックは独立して維持する。
タイムライン表示には見出し直下のサンプル投稿プレビューと表示設定の初期化がある。
リアクション操作はサーバー対応時に表示する。
GIF設定は投稿メディアのgifv再生で使用し、プロフィール画像やカスタム絵文字のアニメーションを
個別に切り替える設定ではない。Dynamic Colorの設定はない。

定期確認通知は登録済みアカウントをJobSchedulerで確認する方式で、プッシュ通知ではない。
OSの通知許可と実行制約に従うため、15分ちょうどの到着は保証しない。
アプリが前景にある間は、Streaming APIのユーザーストリームで通知を即時反映する。接続が切れた場合は再接続する。
対象は閲覧中のアカウントとし、ストリーミング設定に従う。詳細画面や設定画面を開いていても、Activityが前景にあれば接続を維持する。

「起動中のAndroid通知」がオンの場合、前景で受信した通知をAndroid通知にも表示する。表示にはOSの通知許可が必要となる。

Pushはストリーミングとは独立して受信する。Pushと定期確認による通知も、前景では「起動中のAndroid通知」の設定に従う。
定期確認が前景で動作したときに設定がオフであれば、Android通知を表示せずに確認済み位置を進める。

受信時点でAndroid通知の配信対象と判定した通知は、本文を先に表示する。プロフィール画像を取得できた場合は、同じ通知へ後から追加する。

Streaming・定期確認・Pushは配信履歴を共有する。アカウントごとに直近500件の通知IDを記録し、同じ通知の重複配信を抑止する。

通知チャンネルは、既存の「Mastodonの新着通知」を使用する。音とバナーの表示はOSの設定に従う。
Android通知をタップすると、対象アカウントの通知タブ「すべて」を開き、一覧を更新して先頭を表示する。
Android通知の消去対象は、後述の通知欄で読み込んだ通知に従う。Relay／FCMによる実際の通知配信は未接続。

設定 → 通知の「通知を受け取る方法」には、ストリーミングの状態と通信設定への案内、アカウント別Push、定期確認通知を並べる。
「Android通知の表示」には、起動中のAndroid通知の設定を置く。この設定はOS通知の表示だけを制御する。
アカウント別Pushは、外部通知サービスが未設定のため「準備中」と表示し、有効化できない。

サービス接続後は、必要に応じて通知許可や再認証を求める。購読の解除に失敗した場合は、解除待ちとして保存する。
起動時、前景への復帰時、または再試行ボタンの操作時に解除処理を再開する。詳細は[通知設定と購読管理](push-settings.md)を参照。
初期設定ではバックグラウンドでストリームを停止するため、バックグラウンドでの即時到着は保証しない。
ストリーミングのWi-Fi条件は接続開始時に判定する。
通知内の投稿引用はメディア付きなら添付件数を表示する。件数の位置は本文の下のまま、
文字はlabelMediumとする。返信系の通知だけは投稿カードと操作列を表示し、
独立した返信ボタンや通知者と投稿者の重複したプロフィール画像を表示しない。
その他の通知は引用形式を維持する。
通知一覧の種類アイコンは塗りつぶし型に揃え、お気に入りの星は黄色にする。絵文字リアクション通知では、通知したアカウントIDと投稿のリアクション別`account_ids`が1種類だけ一致するとき、その絵文字を表示する。カスタム絵文字は画像URLを使用し、一致しない・複数に一致する・画像の取得に失敗する場合は汎用の塗りつぶしアイコンを表示する。
Androidのシステム通知はステータスバー用の単色の象アイコンに加え、取得できる場合は通知元ユーザーのプロフィール画像を大アイコンに表示する。
通知タブを開いたときと、通知タブを表示したままアプリが前景に戻ったときは、最新の通知を自動取得する。
自動取得中にStreaming APIから受け取った通知もIDで統合し、重複表示や上書き消失を防ぐ。
手動・自動更新とStreaming受信では通知一覧を自動スクロールしない。新着がある場合は「すべて／メンション／リアクション」のフィルター行の下に、ホームと同じ「新着○件」を表示し、タップで「すべて」の先頭へ移動する。先頭に新着が表示されたら既読にしてベルの件数を消し、短時間だけ件数表示を残す。途中を閲覧中は位置と件数表示を保つ。取得失敗時は既読にしない。新着が0件の場合は件数表示を出さない。通知IDで重複を除く。
新着通知の行は背景色を変えて示す。既読になっても、次の更新成功または通知タブを離れるまで背景色を保つ。更新失敗では背景色を消さない。
自動更新では引っ張って更新のインジケーターを出さず、手動更新時だけ表示する。
「すべて」の先頭に最新通知が表示された時点で、そのIDを既読マーカーとして保存する。
通知ごとの既読表現やOS通知から対象詳細への直接遷移は今後の確認・改善対象とする。
通知欄で読み込んだ通知に対応するAndroid通知を一括で消去する。別アカウントや読み込んでいない通知は消去対象に含めない。
既読にした通知は配信履歴にも記録し、遅れて届く同じ通知の再表示を抑止する。
通知一覧は初回・追加取得ごとに最大80件を読み込み、末尾到達時により古い通知を追加取得する。
インスタンスが80件未満に制限しても取得を続け、追加取得に失敗した場合は一覧末尾で再試行できる。

### 通知の端末保存（試験導入）

通知を試験的にDBへ保存する。保存対象は、アカウント・インスタンスごとの最新200件とする。
起動時とアカウント切り替え時は、保存済みの一覧を先に表示してから最新の通知を取得する。

起動時の更新に成功したら、一覧を最新ページに置き換える。保存済みの履歴と新着通知の間に未取得の通知がある場合は、通常の追加取得で順に遡る。
更新中に受信したStreaming通知も保持する。

更新に失敗した場合は、保存済みの一覧を表示し続け、自動では既読にしない。

通知の取得、追加取得、Streaming受信、通知内の投稿操作を一覧へ反映した後、DBの保存内容を更新する。
DBの読み書きに失敗しても、通信による取得と画面表示を継続する。

200件は端末の保存上限であり、オンラインで閲覧できる履歴件数の上限ではない。未読であっても保存上限の対象とする。
投稿本文・通知元の情報は通知と一緒に保存し、上限を超えた通知を保存対象から外すときに一緒に削除する。
既読位置は通知一覧とは別に保存し、件数制限で古い通知が消えても保持する。キャッシュ表示だけでは既読にせず、既読位置の通信取得に失敗した場合は端末の保存値を使用する。
画像本体は既存の画像キャッシュで管理し、通知DBにはURLだけを保存する。期限による一括削除は行わず、ログアウト時に対象アカウント分を削除する。
容量は保存件数で制限し、MB単位の固定上限や利用者向けの件数設定は設けない。通知DBはバックアップ・端末移行の対象外とする。
ホーム・ローカル・連合へのDB導入は[次回以降の計画](release-plan.md#品質基盤候補)として扱う。

## 投稿と下書き

新規投稿・返信・自分の投稿編集に対応する。投稿元、公開範囲、本文、CW、センシティブ指定、
画像・動画添付、ALT編集、投票、カスタム絵文字挿入、メンション候補を扱う。

Androidの共有メニューでテキスト／URLまたは1枚の画像を共有先として受け取る。
ログイン済みなら投稿画面を開き、テキストを本文に、画像を添付に反映する。
未ログインなら共有内容を一時保持し、ログイン完了後に投稿画面を開く。
共有画像は投稿画面でアプリ専用領域へ取り込み、ALT編集と投稿前確認は通常の添付と同じ扱いにする。
文字数や添付上限は投稿元サーバーの設定を取得する。
投票とメディアは併用不可。投票は最大4択、複数選択に対応し、期間の初期値は24時間。
地球アイコンの言語ボタンから中央ダイアログを開き、先頭に「デフォルト」を固定表示する。デフォルトは言語指定を省略してサーバーに委ね、選択した言語は下書き・一時入力にも保持する。投稿編集では元の言語を引き継ぐ。
「#」ボタンは本文のカーソル位置に半角の#を挿入する。ハッシュタグの入力補完は行わない。
投票期間を選ぶUI、添付の並べ替えUIはない。
メディアはシステムの写真選択UIから選ぶ。投稿画面の添付は本文入力欄の下に
2列のタイルで配置する。サムネイル・ファイル名・サイズ・削除操作を表示し、
ALTは編集ボタンからダイアログで入力する。入力済みALTはタイル内で1行に要約する。
メディアを添付してから1秒後に、1件ずつ先行アップロードする。送信画像の縮小や再圧縮は行わない。

添付タイルには、アップロードの進捗率、サーバーでの処理中、ALTの反映中といった状態を表示する。
失敗した場合は、そのタイルから再試行し、エラーの詳細を確認できる。

通信の上限時間と、非同期処理の完了を待つ時間は、それぞれ60秒とする。処理の完了待ちが上限を超えても、失敗とは断定しない。
「再確認」を選択すると、保持しているメディアIDで処理状態を照会する。

エラー詳細と診断ログには、HTTPステータスまたは例外の種類だけを記録する。

投稿時は、待機中のメディアのアップロードを開始する。すべてのメディアの処理と最新ALTの反映が完了するまで待機する。
失敗した添付への自動スクロールは行わない。

添付削除・投稿元切替・画面を閉じる際は先行処理をキャンセルする。下書きには投稿元にひもづけた
メディアIDと最新ALT、ローカルファイルを保持し、復元時にIDを確認する。存在しないIDは元ファイルから再送する。
バーのゴミ箱は確認なしで本文をクリアし、CW・投票・添付と保存済み下書きは変更しない。返信相手のメンションが削除される場合は返信も解除する。

内蔵ブラウザーはJavaScriptとDOMストレージを有効にする。戻る操作は閲覧履歴があれば
前のページへ戻り、履歴がなければブラウザー画面を閉じる。別ウィンドウを開くページや
一部の外部認証・ダウンロードは個別確認が必要で、全Webサイトとの互換性は保証しない。

投稿中・メディア取り込み中は競合する操作を抑止し、ALT未入力時は設定に応じて確認する。
自分の投稿を編集中の場合は、投稿元アカウントを切り替えられない。

返信中に投稿元アカウントを切り替えた場合は、本文のメンションと入力済みテキストを引き継ぐ。
返信先指定と返信元のプレビューは解除する。添付などは切り替え元アカウントの一時バッファに保持し、切り替え先アカウントからは送信しない。

返信元のプレビューは同じアカウント・インスタンスで取得済みの投稿を再利用し、投稿設定や絵文字の取得を待たずに表示する。下書き復元などでキャッシュがない場合だけ返信元の投稿単体を取得する。

本文から返信相手のメンションを削除した場合も、返信先指定と返信元のプレビューを解除して通常投稿へ切り替える。
本文の残り、CW、添付などは保持する。メンションを再入力しても、返信状態には自動で戻さない。

投稿元を切り替える際は、現在の入力を切り替え元アカウントの一時バッファに保存し、切り替え先アカウントの入力を復元する。

下書きを永続保存するには、利用者が保存操作を行う。自動保存の設定はない。

投稿画面を閉じたときの入力内容は、メモリ上の一時バッファに保持する。プロセス終了後の復元は保証しない。

保存済み下書きは、投稿元・返信先・編集対象を含むキーで区別する。
本文、CW、公開範囲、センシティブ指定、添付ファイル情報とALT、投票を保存する。添付ファイルはアプリ専用領域へ取り込む。

保存済み下書きの呼び出しと削除に対応する。下書きを呼び出すと、その下書きを一覧から除き、内容と添付ファイルを編集中の投稿へ移す。
再び下書きとして残すには、保存操作が必要となる。

投稿に成功した場合は、対応する下書きと一時バッファを削除する。保存済み下書き一覧で長押しによる削除を行う場合は、確認ダイアログを表示する。

## プロフィール

画像はヘッダー左下に重ね、編集・フォローボタンと三点メニューは右下に配置する。ユーザーID直下に投稿・フォロー・フォロワー・登録日を一列で表示し、その下にフォロー関係と自己紹介を配置する。アカウント名は折り返して表示する。「フォローされています」はIDと一行に収まる場合はID横、収まらない場合は表示名横へ配置する。三点メニューのポップアップはボタン自体を基準として表示する。

プロフィール項目は自己紹介の下に薄い背景の欄でまとめ、項目間を区切り線で分ける。「補足情報」の見出しは表示しない。リンクとカスタム絵文字を維持し、確認済みリンクは項目の右端に小さなチェックのみを表示する（読み上げラベルは「リンク確認済み」）。項目が空なら追加の表示領域を設けない。

ヘッダー、画像、表示名、アカウント名、自己紹介、プロフィール項目と認証済み表示、
登録日、投稿・フォロー・フォロワー数を表示する。固定投稿と「投稿」「投稿と返信」「メディア」の
タブ、追加読み込みに対応する。フォロー数からアカウント一覧を開く。

自分のプロフィールは表示名・自己紹介・画像・ヘッダー・承認制・プロフィール項目を編集する。
他のアカウントではフォロー状態を表示し、フォロー／解除、ミュート、ブロック、理由付き通報を扱う。
ミュート・ブロックの変更は確認ダイアログを使用する。

プロフィール詳細のメニューに共有・コピー・QR・外部ブラウザーがあり、自分の場合はリスト、
お気に入り、ブックマーク、フォロー中タグ、アカウント設定も表示する。
メインのプロフィールタブのメニューとは項目が異なる。
フォロー中タグとアカウント設定はWebリンクであり、専用のネイティブ画面ではない。
