# ADR 0001：キャンセルと世代番号の照合によるセッション隔離

- 状態：accepted（既存設計の追記）
- 記録日：2026-10-05
- 当初の採用日・比較経緯：不明。以下の理由・代替案の評価・見直し条件は現行仕様と実装を基に今回整理した。

## 背景

複数インスタンスのアカウントを切り替えて利用し、画面の通信・ストリーム・操作結果が非同期で届く。
A→B→Aの切替では、以前のAへの要求と現在のAへの要求をアカウント情報だけでは区別できない。
キャンセルに協調しない処理からも遅延応答が届き得る。

## 決定と理由

`BrowsingSession`のスナップショットにアカウントと世代番号を持ち、セッションの有効化ごとに世代を進める。
`SessionScopedViewModel`は切替時に要求をキャンセルし、画面状態を初期化する。
結果反映前にコルーチンの有効性とスナップショットの一致を確認し、古い応答を拒否する。
ストリーム・操作成功イベントにもスナップショットを添え、現在のセッションに合うものを反映する。
不要な処理の終了と、遅延した結果による別セッションへの混入防止を両方扱うため、この併用を維持する。

## 代替案の評価（今回の整理）

- キャンセルのみ：不要な処理を止められるが、キャンセルに協調しない処理の遅延結果を区別する仕組みが不足する。
- アカウントの一致のみ：A→B→Aの切替後に以前のAの応答を受け入れてしまう。
- 世代照合のみ：結果の混入を防げても、不要になった通信や処理のキャンセルが行われない。

## 受け入れる制約

非同期の結果とイベントを扱う各経路でスナップショットの受け渡しと照合が必要になる。
アカウント切替では一覧状態を初期化するため、全アカウントの画面状態を同時に保持する用途には追加設計が必要。

## 見直し条件

複数アカウントの一覧を同時表示する場合や、共有状態・バックグラウンド処理の所有者を変更する場合に見直す。
変更時も、切替・ログアウト後の遅延応答とA→B→Aの古い応答を拒否する要件を検証する。
