# 0007：種類別通知ページと独立した閲覧記録

- 状態：accepted
- 記録日・採用日：2026-10-06

## 背景

全通知から表示だけを絞る方式では、メンションが他の通知に埋もれ、非対応のリアクション探索も続いていた。
一覧の初回表示が既読取得を待ち、既読位置のIDがページ内にないだけで全件が新着扱いになった。
再起動・時間経過後の新着80件について利用者から報告があり、40件の種類別取得と判定の修正を合意した。

## 決定と理由

各タブに独立した一覧・カーソル・エラー・読込状態を持ち、必要な種類を最大40件ずつ取得する。
種類指定の未対応・拒否・無視は、そのタブの全通知カーソルとローカル絞り込みで扱う。
新規表示対象のないページが連続2ページになれば自動取得を止め、手動取得と履歴末尾を区別する。
リアクションは`fedibird_capabilities`の`emoji_reaction`が確認できた場合のみ取得する。
対応不明・通信失敗は再確認可能なメモリ状態とし、アカウント・セッション世代で隔離する。
同じセッションのタブ再表示では確認結果を再利用し、手動更新・前景復帰・新しいセッションで再取得する。
一覧の表示は既読取得から独立させ、既読取得には5秒の期限と保存値へのフォールバックを設ける。
閲覧済みIDと全通知の閲覧位置を別に永続保存し、待機中の閲覧や一覧の置換で失わない。
RESTの新着はサーバー順のページ内で境界を確認できた場合のみ確定する。IDを数値・辞書順で比較しない。
Streamingで確認した新着は保持し、種類別一覧へ重複を除いて配信する。

## 代替案と受け入れる制約

全通知の共有カーソルを維持する案は遅延・無駄な履歴探索を残す。単純なキャッシュ結合は未取得区間を隠す。
サーバーに種類別既読位置を作る案は標準Markers APIと一致しないため採用しない。
タブごとの表示キャッシュ200件と閲覧ID1,000件を保持する分、保存量は増える。Room v3へ加算的に移行する。
カーソルは保存しない。旧通知・既読位置・ホームは保持し、起動時には最新ページから範囲を確立する。
境界不明時は実際の未読があってもREST新着件数に出ない場合がある。件数は確認できた範囲だけを示す。
「すべて」の先頭表示で全体既読位置を進める既存仕様を維持し、種類別タブは端末の閲覧IDだけを更新する。
Misskey由来の連合通知はログイン先が返す通知として維持する。直接ログインの追加は対象外。
