# 0010: Relay登録v2で購読ごとのVAPID鍵を確定する

- 状態: accepted（本番Relayの互換更新と既存購読1件の移行・通知表示を確認。全購読の移行・新版配布は未完了）
- 記録日: 2026-10-06

## 背景

試験版の全体鍵リストでは、許可サーバーAの鍵でBの配送先にも署名できた。
任意の対応サーバーからのPushを、購読ごとに隔離する必要がある。
公開鍵の事前取得に対応しないサーバーもある。旧登録・配送ID・墓標は維持する。

## 決定と理由

以下は採用時の判断を記録したもの。配送方式と購読上限の後続変更は、後述の「現在の仕様」を参照する。

AndroidはHTTPSのinstance APIと認証済み購読応答から鍵を取得し、Relay登録v2へ渡す。
鍵未取得時は24時間の仮登録を作り、Pushを拒否する。確定成功後だけ端末で有効とする。
管理用認証、P-256点の検証、保存した単調増加revisionで更新と再試行を保護する。
Pushの検証と保存の間にも鍵・revisionを照合する。
鍵変更は即時切替とし、旧鍵の併用や最初のPushからの自動信頼は行わない。
FCMトークン更新は鍵とendpointを維持する。配送エンベロープと解除・取得はv1を維持する。
旧方式の期限付き互換は設定で可能だが、今回の本番移行では猶予期間を設けず旧登録のPush受付を停止した。
更新版Androidの起動時に既存購読を移行する。更新後はv1 PUTで鍵制限を解除できない。
DBは追加マイグレーション、Relay→Androidの順に展開する。旧契約への自動後退は行わない。

## 代替案と受け入れる制約

全体リストへの自動追加は購読の隔離を解決しない。配送要求からの鍵取得は送信元を信頼できない。
旧鍵併用は漏えい・失効時にも旧署名を受け付けるため採用しない。
未起動端末の鍵変更・確定前の通知は欠落し得る。実配送は実機で別途検証する。
初期配布はGoogle Playの限定テスターを想定し、招待コード・APK内の共通秘密は使わない。
Relayの120購読上限は人数の証明ではない。テスター資格のAPI検証は未実装であり、
登録を完全に防御する保証はなく、入口の頻度・容量制限と運用者の部分停止を併用する。

## 現在の仕様（2026-10-14追記）

購読ごとのVAPID鍵の確定、revisionによる更新の保護、旧鍵を併用しない判断は引き続き採用する。
採用時に記録した配送方式と購読上限は、後続のADRで次のように変更されている。

- [ADR 0013](0013-adopt-hybrid-push-delivery.md)でハイブリッド配送を採用した。小通知はv1 inline、大通知はv2 sync_requiredを使い、本文GET・永続再送・毎分の配送Cronは新経路から除いた。採用時の「配送エンベロープと解除・取得はv1を維持する」は、その時点の互換方針を示す。
- [ADR 0015](0015-production-hybrid-cutover.md)の本番切替で、登録上限300・仮登録上限50を採用した。上記の120購読は採用時の上限であり、現在の上限ではない。上限がテスター資格や人数の証明にならない制約は引き続き残る。

現行の配送・上限は[ハイブリッド仕様](../../relay/workers/hybrid.md)、本番の配置・復旧は[本運用手順](../relay-production.md)を参照する。
