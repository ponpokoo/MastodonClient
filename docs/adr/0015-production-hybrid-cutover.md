# ADR 0015：旧APKの大通知欠落を許容して本番Relayを直接切り替える

- 状態：accepted
- 決定日・記録日：2026-10-08。利用者の明示指示による。
- 置換範囲：[ADR 0013](0013-adopt-hybrid-push-delivery.md)のAPK移行後に切り替える条件。
  配送方式・情報境界・端末同期の判断は0013・[0014](0014-android-hybrid-push-sync.md)を継承する。

## 背景

利用者がほとんどいない時間帯で、旧APKがsync_requiredを処理できない影響を許容する指示を受けた。
RelayとAndroid同期は実装済みだが、実FCMの大通知・欠落回復や通信量・遅延の測定は未完了。
方式採用、配置完了、100人向け運用の合格を別の状態として記録する。

## 決定と理由

専用の実FCM環境での先行確認と、全利用者のAPK更新を本番切替の必須条件から外す。
既存nagisa-relayのorigin・D1・購読・FCM設定を引き継ぎ、生成済みハイブリッドコードを配置する。
DBスキーマは0001・0002を利用し、既存テーブルや購読を作り直さない。
毎分の配送Cronを日次清掃へ変更する。登録上限300・仮登録50を採用する。
切替前のCloudflare版IDを記録し、通常の版復元で差し戻せるようにする。

## 代替案・受け入れる制約

- 対応APKの配布後に段階移行：旧APKの大通知を保護できるが、今回は指示により省略する。
- 旧配送を併用：本文保存・永続再送・旧fetchの運用負担が残るため採用しない。
- 旧APKでは小通知のinline表示は継続し、大通知のsync_requiredは表示できない。
- 切替前のfetch通知・配送待ちジョブは新経路で取得・再送しない。既存行は削除しない。
- Relayの永続再送を失い、旧APKには新Androidの差分補完機能がない。

## 見直しと関連文書

小通知の配送障害・登録や解除の障害が生じた場合は部分停止または旧版へ差し戻す。
大通知の実FCM確認、APK配布、CPU・通信量・遅延・長時間運用の測定は引き続き実施する。
配置状態・差し戻し手順は[本運用手順](../relay-production.md)、現行仕様は[ハイブリッド仕様](../../relay/workers/hybrid.md)を正本とする。
