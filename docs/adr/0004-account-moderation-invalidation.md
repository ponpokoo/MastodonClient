# ADR 0004：ミュート・ブロック成功後の共有非表示状態とキャッシュ除去

- 状態：accepted
- 記録日・採用日：2026-10-05

## 背景

ミュート・ブロックのAPI成功だけでは表示中の投稿・通知が残る。
キャッシュだけを削除しても、操作前に始まった通信・Streaming・保存処理が古い内容を戻すことがある。
ホーム・通知はRoomに保存し、他の画面はViewModelごとに表示状態を持つ。

## 決定と理由

Repositoryが確認済みの関係変更をセッション・インスタンス・対象アカウント別のStateFlowで共有する。
各ViewModelは共通の表示フィルターを通して状態を公開し、非表示にした行を内部状態からも除く。
投稿者・ブーストした人、通知者・通知内の投稿への参照を判定する。
通知抑制を無効にした既存ミュートはサーバーの関係情報を尊重する。
ホーム・通知のローカルデータソースは対象を削除し、書き込みの排他区間でも同じ非表示条件を適用する。
API成功後のローカル反映は画面のキャンセルで中断せず、保存失敗をサーバー設定の失敗として扱わない。
解除は削除済みの古い行を復元せず、次の通信取得でサーバーの結果を採用する。
対象プロフィールの投稿取得は非表示中に止め、空になった一覧の残存カーソルから追加取得を繰り返さない。

## 代替案と受け入れる制約

- 成功後の全画面再取得：表示の消失が通信完了まで遅れ、保存やStreamingとの競合も残る。
- 全画面をDBから購読：整合の集約は可能だが、現行の保存範囲・スキーマを大きく変える。
- 設定一覧の永続複製：プロセス終了をまたぐ設定管理には使えるが、期限・別クライアントの変更との同期が必要。

採用方式では共有状態はプロセス内に限り、DBからの行削除は再起動後も残る。
サーバーの設定を正本とし、全設定の定期同期・管理一覧・OS通知の一括消去は今回の対象外。
セッション隔離とキャンセルは既存の[ADR 0001](0001-session-isolation.md)、DBの範囲は[ADR 0002](0002-persistent-browsing-cache.md)を維持する。
