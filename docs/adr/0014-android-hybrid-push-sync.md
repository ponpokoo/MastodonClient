# ADR 0014：AndroidのハイブリッドPushを永続世代と差分位置で補完する

- 状態：accepted（Android実装。Relay本番切替済み、実FCM測定・対応APK配布は別途）
- 決定日・記録日：2026-10-07
- 関連：[ADR 0013](0013-adopt-hybrid-push-delivery.md)の端末同期を具体化する。

## 背景

本文を保持しないRelayの大通知は同期要求だけになり、端末側の欠落回復が必要になる。
同期中にも新しい要求が到着し、プロセス停止や購読変更を跨いで要求が失われてはいけない。
通知IDは不透明なStringで、単純な数値比較や閲覧中のアカウントへの配送はできない。

## 決定と理由

要求・完了世代、同期位置、初期化状態と同期途中の表示済みIDを暗号化した購読記録に持つ。
アカウントごとのUnique WorkにAPPEND_OR_REPLACEで積み、3秒待機して最新の要求世代をまとめて取得する。
後続Workは処理済みならAPIを呼ばない。登録・資格を取得前後と表示・保存時に照合する。
解除・ログアウト・再認証では同期Workを取り消し、購読削除で同期情報も破棄する。
v1 Notifications APIのsince_idとmax_idを使い、全ページ成功後だけ位置を更新する。
新規購読は購読作成前に最新1件から開始位置を設定し、過去の大量再通知を避ける。
位置のない既存購読は直近1ページから開始する。Push／欠落起点だけ初回ページを表示対象にする。
起動・前景・通知更新は未完了または15分経過時に補完し、FCM欠落は無条件で要求する。

## 代替案と受け入れる制約

- KEEPのみ：終了直前の要求を失い得る。永続世代と後続Workにより次の取得機会を確保する。
- REPLACEで毎回取消：集中時に取得を完了できないため採用しない。
- 初回全履歴：APIと大量の過去通知の負担が大きい。既存購読の初期化前の完全回復は保証しない。
- Work数は集中時に増えるが、同じ世代のAPI取得は集約する。3秒とOS制限による表示遅延を受け入れる。
- 本文はメモリ内のみ。通知表示と保存の原子性、共有履歴500件外の重複排除は保証しない。

## 見直し条件と関連文書

実機のAPI回数・通信量・電池・遅延、長期欠落・大量のページ・Work滞留を測り、待機時間と補完間隔を再評価する。
