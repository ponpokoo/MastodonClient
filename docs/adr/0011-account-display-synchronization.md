# ADR 0011：登録済み自アカウントの表示情報と認証セッションを分離

- 状態：accepted
- 記録日：2026-10-07

## 背景

登録情報は認証時の表示名・ユーザー名・アイコンのままで、プロフィールの再取得結果が切替・投稿画面へ届かなかった。
表示同期の導入前の`saveSession()`は対象を末尾へ移して選択するため、表示更新への流用では登録順と選択状態が変わった。
`AccountSession`には認証情報も含まれ、全体の変更を閲覧セッションの変更として扱うと投稿入力や一覧・ストリームに影響する。

## 決定と理由

認証RepositoryとプロフィールRepositoryが同じ表示情報同期処理を共有し、取得済み応答を既存の登録へ反映する。
起動・切替では保存情報を表示後に背景再取得する。プロフィール取得・編集では追加API通信を行わない。
同期要求は切替・ログアウト・再認証の世代と、アカウントごとの要求開始順で隔離する。キャンセルも保存前に確認する。
保存・削除・認証置換はDataStoreの原子的な編集内で行い、表示更新時は登録と認証情報を再確認する。
表示情報と画像更新番号だけを元の位置で更新し、登録一覧のFlowを各ViewModelへ配信する。
閲覧スナップショットは認証情報と世代を保ち、表示変更で再有効化しない。認証照合は専用の比較を使う。
同じURLの画像も更新できるよう、対象アイコンのキャッシュキーに永続化した更新番号を含める。

## 代替案と受け入れる費用

- `saveSession()`の再利用：順序・選択に副作用があるため採用しない。
- 各ViewModelで個別保存：取得経路間の競合を排除できず、同じ照合を重複するため採用しない。
- 全画像キャッシュ削除：他の画像の再取得まで発生するため採用しない。
- 同期成功時は表示情報が同じでも画像の再取得が起こる。旧キーはCoilの通常の容量制限で除去される。
- 最新要求が失敗しても、以前に開始した応答は保存しない。保存情報を保ち、次回の取得で再試行する。
- 同期の世代はアプリ内で共有する。プロセス終了後に古い通信が復帰することはなく、保存済み形式の移行は更新番号0で互換にする。

Issue #11対応で認証保存も既存位置を保つよう変更したが、選択変更の副作用があるため表示同期には引き続き専用の保存操作を使う。
Issue #10の確認対象照合からPush解除・削除までは既存の登録変更Mutexで直列化する。待機の費用と現行仕様は[開発ガイド](../project-setup.md#アカウントの削除確認と保存順)を参照する。
