# ADR 0009：小規模Relayの実装・検証先にWorkersとD1を継続利用する

- 状態：accepted（実装・検証先の選定。Freeでの公開可否は未判定）
- 記録日：2026-10-06

## 背景

最大30人程度、予算0円、開発者1人によるベストエフォート運用を前提に本運用を準備する。
既存Workers版には実FCM送信、D1保存、VAPID検証と過去の実配信記録がある。
ただし購読単位の鍵制限、濫用防止、容量、再送、監視・復元は本運用向けの変更・検証が必要。

## 決定と理由

本運用向けの実装・検証先はCloudflare Workers＋D1とし、初期はFreeで検証する。
D1を未送信状態の正本とし、現行の受付後送信とCronを出発点に再送能力を設計する。
既存origin・配送ID・墓標を維持する移行を優先し、独自ドメインの費用を追加しない。
FCM情報はSecrets、復元はTime Travelと変更前のSQL退避、監視はMetricsと利用可能なCustom Alertsを使う。
移植量とOS・TLSの運用負担を抑え、既存の情報境界と試験資産を利用できるため選ぶ。

## 代替案

- Workers Paid：同じ実装で制約を緩和できるが、月額最低5 USDと超過課金が0円予算に合わない。
- 全通知をQueuesへ投入：通常3,600件/日でも通常3操作で無料10,000操作/日を超える。失敗分だけの利用は再送設計時に比較する。
- 管理コンテナ：DB・背景処理・監視を含む再構成とWorkers固有APIの移植が必要で、一式の0円成立は未検証。
- VPS：本番用実装の整備に加え、1人でOS・TLS更新と復旧を担当する費用・負担が増える。

## 受け入れる制約

FreeのHTTP・Cron CPU 10ms、D1の容量・日次使用量・実行クエリ数を実配置で検証する。
現行の毎分1件の再送は本運用目標を満たさず、再送方式の詳細は手順3で決める。
個人用途のworkers.devを使う制約、無料枠到達時の停止、通知欠落、地域固定の保証がないことを受け入れる。
公開許可・新契約の採用・クラウド配置を完了した判断ではなく、旧試験版をそのまま公開しない。

## 見直し条件

CPU・再送・保存・復元・監視が目標を満たさない場合、または予算・規模・地域要件が変わる場合に再評価する。
Paid・Queues・他環境への変更は費用、旧クライアント互換性、保存情報とURLの移行条件を記録して判断する。
