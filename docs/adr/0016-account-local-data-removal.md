# 0016: アカウント登録削除にローカルデータの回収を含める

- 状態: accepted
- 記録日: 2026-10-08

## 背景

登録だけを消すと、旧セッションIDに結び付いた下書き・添付・設定・履歴が取り出せないまま残る。
認証、通常設定、ファイル、Room、Android通知は保存先が異なり、一つのトランザクションでは削除できない。
削除中にも添付の取り込み、通知、下書き保存などの非同期処理が完了し得る。

## 決定と理由

登録削除は対象の下書き・入力バッファ・添付コピー・アカウント別設定・履歴・通知・閲覧DBを回収する。
アプリ共通設定、他の登録、共有画像キャッシュ、元の写真・共有ファイル、サーバー上の投稿は保持する。
認証削除と同じDataStore編集でセッションIDだけの削除待ちを保存し、ローカル回収完了後に消す。
保存先の一部が失敗しても認証を戻さず、起動・前景復帰時に再試行する。
Repositoryが削除の順序と再試行を担い、各保存先の操作はLocalDataSourceへ委譲する。
通常設定のアカウント別書き込みは登録存在をDataStore編集内で確認する。
新しい添付コピーはセッション別ディレクトリへ保存し、取り込みと回収を同じMutexで直列化する。
従来の平坦な添付ファイルは下書き・入力の参照を回収し、参照削除と同時にファイル削除待ちを保存する。
通知表示・通知履歴更新・取得位置更新と通知削除も共通Mutexで直列化し、遅延通知には登録を再照合する。

## 代替案と受け入れる制約

下書き保持には再ログイン後の復元・削除UIが必要なため、今回はユーザー指定の一括削除を採用する。
削除途中の全ロールバックは通知やファイルでは保証できず、ログアウトを妨げるため採用しない。
新形式の添付は未保存でも回収できる。更新前から参照を失っていた旧形式ファイルの一括消去は行わない。
過去のOSバックアップを遡って消去する保証はしない。削除待ちID・ファイルパスは回収まで残り得る。
Push解除待ちの旧認証情報は従来の暗号化保存・再試行仕様を維持し、本判断で保存期限を新設しない。
