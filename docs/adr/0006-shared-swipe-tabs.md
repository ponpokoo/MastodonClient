# 0006: スワイプの選択表示とデータ取得の分離

- 状態: accepted
- 記録日・採用日: 2026-10-05

## 背景

探索・検索結果・通知・プロフィールで、横スワイプの制御が別々だった。
通知は移動途中のページで選択を更新し、探索・検索は移動完了後に更新していた。
プロフィールは選択表示を途中で更新し、移動先候補の一覧を先読みしていた。
通知は取得済み一覧を絞り込めるが、他の一覧ではサーバー通信が必要になる。
操作感を揃えつつ、途中で戻したスワイプや離れたタブへの移動で不要な通信を避けたい。

## 決定と理由

UI共通部品 `rememberSwipeTabs` にページ移動と選択通知を集約する。
選択表示は移動途中の `currentPage` に追従する。
スワイプでは、スクロールとアニメーションが完了した `settledPage` の選択だけを通知する。
タブを直接押した場合は押した先を直ちに通知し、途中のページは通知しない。
通知・プロフィールの自動追加取得も横移動中は待つ。
通信・キャッシュ・セッション隔離は既存のViewModel以下に残す。

## 代替案と制約

移動途中にすべての選択を通知する方式は、通信の重複やキャンセルが増えるため採用しない。
移動先候補の先読みは表示待ちを短縮できるが、操作を戻した際にも通信が発生するため採用しない。
未取得の一覧はスワイプ完了後に通信を始めるので、その分だけ表示待ちが発生する。
取得済みの一覧とスクロール位置は、引き続き画面・タブ別に保持する。
メインの下部ナビゲーションとメディアビューアはこの制御の対象外とする。

## 見直し条件・関連文書

表示待ちが問題となる場合は、通信量・キャンセル・セッション隔離を評価して先読みを再検討する。
現行の操作仕様は[UI・機能仕様](../ui-guidelines.md#画面構成)、取得の隔離は[開発ガイド](../project-setup.md)を参照する。
