# 完了したUI修正の要点

統合日：2026-10-06。音声・プロフィール・検索の調査記録から、再発時に必要な原因・修正理由・確認範囲を残す。
各結果は記載した変更段階の確認であり、今後のRelease APKの検証結果ではない。対象版の配布前確認は[リリース計画](../release-plan.md)で管理する。
現行動作は[UI・機能仕様](../ui-guidelines.md)、確認方法は[開発ガイド](../project-setup.md#ビルドと確認)を参照する。

## 音声と動画の再生

- 原因：`audio`はDTO・ドメインへ届いていたが、投稿とビューアのUIが画像として扱い、音声再生へ進めなかった。
- 修正：メディア種別で音声を分岐し、共通のMedia3プレイヤーで添付本体の`url`を再生する。拡張子で判定せず、`preview_url`を音源へ代用しない。別メディアの再生・画面外・背景移行で停止し、破棄時に解放する。
- 調整：シーク・秒送り・音量・ミュート、横画面の操作部、映像タップによるUI切替、左右の切り欠きへの対応を追加した。
- 確認：2026-10-03、Android 17の最終段階の関連端末30件、その後の横画面11件、切り欠きと回帰4件が各段階で成功。2.3.0リリース時には利用者から実配信・可聴確認・最終UIの実機確認済みとの報告を受けた。すべての端末・コーデックへの対応を保証しない。

## プロフィール文の改行

- 原因：本文中のUnicode行区切り`U+2028`はHTML変換後も残るが、確認したComposeの表示では1行になった。
- 修正：HTML変換後の`U+2028`だけをLFへ置換する。文字数を変えず、リンク注釈とカスタム絵文字の位置を保持する。HTML中の通常のLFや`U+2029`は変更しない。
- 確認：2026-10-05、Android 17の`StatusContentTextDeviceTest`2件が成功。2行表示、前後のリンク操作、既存のHTML改行変換を確認した。
- 別件：プロフィール編集は表示用HTMLから本文を復元しており、編集用平文`source.note`による改行・末尾空行の保持は未対応。[Issue #9](https://github.com/ponpokoo/MastodonClient/issues/9)で管理する。

## 固定投稿の先頭表示と同時表示

- 原因：通常投稿の後に固定投稿を先頭へ追加すると、`LazyColumn`が元の先頭投稿のキーで閲覧位置を保ち、固定投稿が上側へ隠れた。
- 修正：先頭かつスクロール操作中でない場合だけ、固定投稿変更後の再計測で先頭位置を指定する。閲覧中の投稿・オフセットは維持する。
- 取得：通常投稿と固定投稿を並行取得し、両方が揃ってから一度に反映する。プロフィール情報は先に表示し、固定投稿の失敗時は通常投稿を表示する。再取得失敗時は既存の固定投稿を残し、古いセッション・キャンセル済み要求の結果を反映しない。
- 確認：2026-10-05、UI修正時に固定投稿の端末3件とタブ切替4件が成功。同時表示への変更後はプロフィールViewModelの単体17件とDebugコンパイルが成功し、端末テストは再実行していない。

## プロフィールの惰性スクロール

- 原因：ヘッダー側の一覧から始めたスワイプでは、ヘッダーが隠れた後の移動量が投稿一覧へ渡らず、最初の固定投稿で止まった。
- 修正：ヘッダーで消費しきれない下向きの移動を、選択中の投稿一覧へ引き継ぐ。投稿一覧自身の操作・横タブ移動中には引き継がず、惰性中の触り直しで停止・逆方向への操作ができるようにする。
- 確認：2026-10-05、Android 17のスクロール回帰2件、固定投稿3件、タブ切替4件、調査用16件が成功。修正版2.4.0 APKについて、利用者から実機で解決済みとの報告を受けた。
- 限界：画像取得・描画時間は測定しておらず、個々の引っかかりの原因やフレーム落ちがないことを保証する結果ではない。

再現用の[調査テスト](profile-pinned-scroll/tests/ProfilePinnedScrollInvestigationTest.kt)と[init script](profile-pinned-scroll/investigation.init.gradle)は通常テストから分離して残す。必要時に以下で実行する。


## 検索復帰時のキーボード

- 原因：検索結果の表示状態を入力開始にも使っていたため、詳細から戻る際に自動フォーカスが再発した。検索確定時もキーボードを隠すだけでフォーカスが残っていた。
- 修正：検索確定時にフォーカスを解除し、結果表示と入力開始を分離する。戻った際は検索語・対象・結果・閲覧位置を保持し、入力欄タップ・検索アイコン・タグ検索で入力を再開する。
- 確認：2026-10-06、検索ViewModelの単体7件、Android 17の入力5件と詳細復帰1件、Debugアプリ・テストAPK生成が成功。利用者から実端末で修正確認済みとの報告を受けた。2.4.1のRelease APKでの確認は配布前に行う。

## 検索・ハッシュタグの投稿メニュー（2026-10-07）

- 対象：[Issue #13](https://github.com/ponpokoo/MastodonClient/issues/13)と[Issue #14](https://github.com/ponpokoo/MastodonClient/issues/14)。提供された調査書の原因を現在の実装でも確認した。
- 原因：検索結果と探索トレンドはメニューの空コールバックへ到達し、ハッシュタグ一覧はメニューのコールバックを渡していなかった。
- 修正：検索・トレンドをメイン画面の既存メニューへ接続。タグRouteに専用の既存StatusActionsViewModelを供給し、共通のメニュー・確認・報告・リスト選択と編集遷移・操作メッセージを接続した。対象は元投稿のstatusIdとauthor.idを使う。
- セッション：タグ画面のメニュー・確認・報告・リスト選択とSnackbarをsessionKeyで破棄する。SearchContentとSocialStatusのメニュー引数を必須にして接続漏れを検出する。APIや投稿変換、詳細の祖先・返信カードは変更していない。
- 確認：検索・タグ・関係操作の関連単体16件、Debugアプリ・テストAPK生成が成功。Pixel_10a（Android 17）の新規回帰5件で、検索・トレンドの2件目の本文コピー、ブースト元の報告・編集・固定・削除、関係取得の再試行、失敗のSnackbar、削除キャンセル・一覧反映、切替時のメニュー・確認・報告破棄を確認した。既存の検索入力5件・詳細復帰1件・探索3件も成功し、端末テストは計14件。実サーバーへの投稿・報告等は行っていない。
- 検証範囲：ビルド成功後、別途変更中のSecureAuthStoreで`acct`の未解決参照が発生したため、端末テストは直前に生成済みのAPKで実行した。後続の認証変更を含む作業ツリー全体やRelease成果物の検証結果とは扱わない。
