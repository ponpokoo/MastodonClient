# プロフィールの固定投稿が先頭に見えない不具合

調査・修正日: 2026-10-05。

## 最初の調査で確認した原因

変更前は、自分のプロフィールと他のアカウントのプロフィールで、ヘッダーを先に表示し、通常投稿を取得して表示した後に固定投稿を取得していた。
`ProfileContent`は固定投稿と通常投稿をこの順で結合し、投稿IDで重複を除いているため、表示データの順序自体は正しかった。

投稿一覧の`LazyColumn`には投稿の`timelineId`をキーとして指定している。
通常投稿の表示後に固定投稿が先頭へ入ると、一覧は元の先頭投稿のキーを基準にスクロール位置を維持する。
このため、一覧をスクロールしていなくても通常投稿が先頭に見え続け、固定投稿は画面の上側へ隠れていた。

合成データで通常投稿を表示してから固定投稿を追加すると、修正前は先頭の表示キーが`pinned`ではなく`post-0`のままになることを端末テストで再現した。
同時に、スクロール済みの場合の閲覧位置維持は正常だった。

## 先頭位置の修正

共通のプロフィール表示部品で、固定投稿のIDと順序が変わる前の一覧位置を記録する。
「投稿」タブの先頭（インデックス0・オフセット0）で、スクロール操作中でなければ、`requestScrollToItem(0)`で先頭を指定する。
このAPIは次の再計測で投稿キーによる位置維持に優先する。[AndroidXの実装・説明](https://github.com/androidx/androidx/blob/androidx-main/compose/foundation/foundation/src/commonMain/kotlin/androidx/compose/foundation/lazy/LazyListState.kt)を参照。

すでに投稿をスクロールしている場合は、既存のキーによる位置維持を使い、読んでいる投稿やオフセットを変えない。
プロフィールのヘッダー位置や他の投稿タブの位置は変更しない。
最初の修正では取得順序やViewModelの非同期処理を変更せず、自分・他人のプロフィールへ共通の表示修正を適用した。

## 通常投稿・固定投稿の同時表示

同日にユーザーが「多少遅れても同時に現れる」動作を指定したため、両方のプロフィールViewModelを変更した。
通常投稿と固定投稿を同じリクエストのコルーチンスコープで並行取得し、両方の結果が揃ってから1回の状態更新で反映する。
固定投稿の取得が終わる前に通常投稿だけを表示し、後から先頭へ挿入する表示を避けるための変更。

プロフィール情報の先行表示は維持する。再取得中は既存の投稿を表示し、取得結果が揃ったら置き換える。
固定投稿の取得に失敗した場合も、通常投稿の結果を反映する。再取得時は既存の固定投稿を保持する。
表示開始までの時間は遅い側の取得に依存する。通常投稿・固定投稿を順番に取得して待ち時間を加算する方式は採用しない。

読み込み中のフラグは両方が終わるまで維持し、待機中に追加読み込みが同じタブの取得を置き換えないようにする。
両方の取得はタブの要求ジョブに属する。自分のプロフィールではセッション照合を反映直前に行い、他人のプロフィールでは再取得時のキャンセル確認を維持する。
「投稿と返信」「メディア」の取得には固定投稿を追加しない。

## 先頭位置の修正時の確認

Pixel_10a（Android 17）で`connectedDebugAndroidTest`に`io.github.ponpokoo.mastodonclient.ProfilePinnedStatusesDeviceTest`を指定して実行し、次の3件が成功した。

- 固定投稿が遅れて届いても、未スクロールの一覧で先頭に表示され、固定のラベルも見える。
- 通常投稿を数件スクロールした後に固定投稿が届いても、閲覧中の投稿とオフセットが維持される。
- 最初の通常投稿を途中までスクロールした場合も、閲覧位置が維持される。

同コマンドでアプリとテストのDebugビルドも成功した。Mastodonアカウントや外部への投稿操作は使用していない。

続けて同じ端末で`io.github.ponpokoo.mastodonclient.ProfileTabSwipeDeviceTest`を対象指定し、既存の4件も成功した。
ドラッグ中と指を離した後のタブ選択、左右端でのスワイプ、離れたタブへのタップ、戻ったときの投稿の閲覧位置復元を確認した。

関連: [プロフィールの現行仕様](../ui-guidelines.md#プロフィール)、[確認範囲の選び方](../project-setup.md#ビルドと確認)。

## 同時表示の確認（2026-10-05）

`:app:testDebugUnitTest --tests '*OwnProfileViewModelTest' --tests '*AccountProfileViewModelTest' :app:compileDebugKotlin`で対象の単体テスト17件とDebugコンパイルが成功した。
通常投稿・固定投稿のどちらが先に完了しても片方だけを表示しないこと、固定投稿の取得失敗時にも通常投稿を表示すること、再取得失敗時に以前の固定投稿を維持することを確認した。
キャンセルを無視して遅れて返る固定投稿についても、アカウント切り替え後や再取得後の新しい投稿を上書きしないことを確認した。
UIの先頭位置の制御は変更していないため、成功済みの端末テストはこの変更後には再実行していない。
