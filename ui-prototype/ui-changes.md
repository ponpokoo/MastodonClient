# UI変更履歴と本体への移植

この文書では、本体へ未適用の試作差分だけを管理する。本体への反映は、別途依頼があってから行う。

本体の現行仕様は[UI・機能仕様](../docs/ui-guidelines.md)、試作の再現範囲は[README](README.md)を参照する。この文書は試作との差分と移植の参考資料として扱う。

## 移植後の記載整理

本体への移植と必要な動作確認が完了した項目は、この文書の差分表・調整履歴・詳細説明から該当箇所を削除する。「適用済み」の項目を残し続けず、未適用の変更を参照する文書として維持する。一部だけ移植した場合は、残る差分と未確認事項を残す。

READMEの対応する差分記載も削除し、参照がなくなった比較画像を削除する。移植内容・適用日・確認結果はPRまたはコミットの説明に記録し、過去の記載はGit履歴で参照する。本体の仕様・手順が変わる場合は、対応する現行文書を更新する。

## 現在の差分と適用状況

| 項目 | 本体の基準 → 現在の試作 | 本体への適用 |
| --- | --- | --- |
| 添付画像の開閉遷移 | Dialogによる全画面表示 → 共通描画レイヤーと一つの進行率でサムネイルから拡大し、画像描画後に表示を引き継ぐ。閉じ始めに閲覧画像と戻り先を固定する。戻る動きは滑らかに減速して揺れずに止まり、投稿ボタンを画像より手前へ自然に表示する | **未適用** |
| 下ドラッグの閉じる遷移と競合回避 | 試作では全画面まで広がった時点から下ドラッグを受け付け、読込待ちや表示引き継ぎ中も指を追跡する。指を離した位置・背景の薄さから直接サムネイルへ戻る。下ドラッグ中の2本指への切替は閉じる操作を中止し、ピンチへ引き継ぐ | **未適用** |
| 拡大中のタップと画像移動の競合回避 | 本体では微小な移動でも画像ドラッグとしてタップを取り消す → 試作では画面上の移動量が端末のドラッグ判定距離を超えてから画像移動を開始する。開始後の方向反転とピンチから1本指への切替は引き続き移動できる | **未適用** |
| 画像ビューアの操作UI背景 | 試作ではグレー（#303030、不透明度35%）の背景で操作UIを囲む。戻る・保存ボタンは直径32 dpの丸い背景と20 dpのアイコン、枚数表示は角丸8 dp・余白左右8 dp・上下4 dp。タップ領域を保ち、操作UIの切替・開閉・下ドラッグに連動させる | **未適用** |
| 遷移中の背面画面・表示領域の保持 | 試作では遷移中のInsetsを固定し、非表示タブの最後の表示領域を保持 | **未適用** |

固定ダークテーマ、固定投稿・画像、空の検索・通知一覧、通信・認証・保存の代替処理は試作環境の制約であり、本体への移植対象に含めない。プロフィールURLのリンク表示もプロフィール欄の表示確認用であり、本体への移植対象に含めない。元々本体と共通の動作も「新しい変更」とは扱わない。

## 以前から残る画像遷移などの差分

詳細な挙動は[READMEの画像遷移](README.md#復元した画像遷移)と[再現範囲](README.md#再現範囲)を参照する。いずれも本体へ未適用。

- 開く遷移は300 ms。ボタン・Androidの戻る操作では拡大・移動を150 msで戻し、角丸を110 msで付けてから、300 msで滑らかに減速してサムネイルへ戻る。戻り先で揺れずに止まり、完了後はすぐに開き直せる。下ドラッグでは離した位置と背景の薄さから直接戻る。短い下ドラッグの取り消しは420 ms。画像切替後の戻り先と、開く途中の戻る操作も含む。
- 閲覧画像の描画が準備できた後、100 msで遷移画像から表示を引き継ぐ。開く途中の戻る操作は現在の進行率から反転し、戻り先がない場合はフェードで閉じる。詳しくは[READMEの画像遷移](README.md#復元した画像遷移)を参照する。
- 上下で見切れたサムネイルは、実際に見えている範囲から徐々に広がり、閉じると元の見切れ方へ滑らかに戻る。画像の位置・倍率と、一覧の表示領域による切り抜きは分けて計算する。
- 実装の入口は[PrototypeImageTransition.kt](src/main/java/io/github/ponpokoo/transitionprototype/PrototypeImageTransition.kt)と[PrototypeApp.kt](src/main/java/io/github/ponpokoo/transitionprototype/PrototypeApp.kt)。`StatusCard.kt`、画像ビューア、画面のInsetsにも接続箇所がある。
- 本体へ採用するときは、本体の画面構成に合わせて接続し直す。固定Repositoryや試作専用namespaceへの依存をそのまま移さない。画像遷移の採用範囲は個別に判断する。

画像関連には[試作の端末テスト](src/androidTest/java/io/github/ponpokoo/transitionprototype/PrototypeImageTransitionDeviceTest.kt)があるが、この記録の作成時には再実行していない。本体での画像読込、画面離脱、戻る操作、操作中断、システムバーとスクロール位置、フレーム性能は移植後に別途確認する。

## 本体へ移植するときの手順

1. 採用する項目を決め、この文書の「未適用」を維持したまま移植に着手する。本体と試作の最新版を確認する。
2. リポジトリ直下で以下を実行し、本体の更新と試作との差分を確認する。

   ```powershell
   python ui-prototype/import-production-ui.py --check
   python ui-prototype/import-production-ui.py --diff
   ```

   `--check`の成功は移植完了やUIの一致を意味しない。`ADAPTED`は試作が取り込み基準と異なることを示す。`--refresh`は本体から試作へ取り込む操作であり、本体へ移植するコマンドではない。
3. 選んだ差分だけを本体へ反映する。画像遷移の接続や固定データへの依存があるため、試作のファイル全体で本体を上書きしない。リソースが必要な変更では本体のnamespaceに合わせる。
4. [開発ガイド](../docs/project-setup.md)に従って変更範囲のビルド・テストを実施する。画像遷移では本体の画像読込、画面離脱、戻る操作、操作中断、システムバーとスクロール位置を確認する。タイムライン・投稿詳細・自分と他者のプロフィールなど、変更が影響する入口から確認する。
5. 本体での動作確認後、移植内容・適用日・確認範囲をPRまたはコミットの説明に記録し、[移植後の記載整理](#移植後の記載整理)に従って該当箇所を削除する。残る項目は「未適用」のままにする。
6. 本体と試作の対応を確認したファイルについて、取り込み基準を更新する。画像遷移を採用する場合は、変更したファイルを指定する。以下は投稿と画像ビューアを変更した場合の例。

   ```powershell
   python ui-prototype/import-production-ui.py --record app/src/main/java/io/github/ponpokoo/mastodonclient/feature/status/StatusCard.kt --record app/src/main/java/io/github/ponpokoo/mastodonclient/feature/media/MediaViewerScreen.kt
   ```

   `--record`は本体のハッシュを記録するだけで、コピー・マージ・テストを行わない。画像遷移など未適用の差分が残れば、記録後も`ADAPTED`が表示される。

完了とする条件は、選んだ変更が本体に入り、本体の画面・データと組み合わせた確認を終え、残る差分と未確認事項を区別できること。試作の確認だけで本体への適用済みにはしない。
