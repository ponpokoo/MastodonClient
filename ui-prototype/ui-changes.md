# UI変更履歴と本体への移植

この文書では、本体へ未適用の試作差分だけを管理する。本体への反映は、別途依頼があってから行う。

本体の現行仕様は[UI・機能仕様](https://github.com/ponpokoo/MastodonClient/blob/main/docs/ui-guidelines.md)、試作の再現範囲は[README](README.md)を参照する。この文書は試作との差分と移植の参考資料として扱う。

## 移植後の記載整理

本体への移植と必要な動作確認が完了した項目は、この文書の差分表・調整履歴・詳細説明から該当箇所を削除する。「適用済み」の項目を残し続けず、未適用の変更を参照する文書として維持する。一部だけ移植した場合は、残る差分と未確認事項を残す。

READMEの対応する差分記載も削除し、参照がなくなった比較画像を削除する。移植内容・適用日・確認結果はPRまたはコミットの説明に記録し、過去の記載はGit履歴で参照する。本体の仕様・手順が変わる場合は、対応する現行文書を更新する。

## 現在の差分と適用状況

現在、本体へ未適用のUI変更はない。画像表示・開閉・操作の現行仕様は
[mainのUI・機能仕様](https://github.com/ponpokoo/MastodonClient/blob/main/docs/ui-guidelines.md#投稿詳細と画像ビューア)を参照する。

固定ダークテーマ、固定投稿・画像、空の検索・通知一覧、通信・認証・保存の代替処理は試作環境の制約であり、
本体への移植対象に含めない。プロフィールURLのリンク表示もプロフィール欄の表示確認用とする。
本体側に追加された機能や試作の再現範囲は[README](README.md#再現範囲)で確認する。

## 本体へ移植するときの手順

1. 採用する項目を決め、この文書の「未適用」を維持したまま移植に着手する。本体と試作の最新版を確認する。
2. リポジトリ直下で以下を実行し、本体の更新と試作との差分を確認する。

   ```powershell
   python ui-prototype/import-production-ui.py --check
   python ui-prototype/import-production-ui.py --diff
   ```

   mainと試作を別のworktreeで開いている場合は、各コマンドに`--production-root C:/path/to/main-checkout`を付ける。指定した本体の作業ツリーを読み取り、試作側のコピーと取り込み基準を比較する。

   `--check`の成功は移植完了やUIの一致を意味しない。`ADAPTED`は試作が取り込み基準と異なることを示す。`--refresh`は本体から試作へ取り込む操作であり、本体へ移植するコマンドではない。
3. 選んだ差分だけを本体へ反映する。画像遷移の接続や固定データへの依存があるため、試作のファイル全体で本体を上書きしない。リソースが必要な変更では本体のnamespaceに合わせる。
4. [開発ガイド](../docs/project-setup.md)に従って変更範囲のビルド・テストを実施する。画像遷移では本体の画像読込、画面離脱、戻る操作、操作中断、システムバーとスクロール位置を確認する。タイムライン・投稿詳細・自分と他者のプロフィールなど、変更が影響する入口から確認する。
5. 本体での動作確認後、移植内容・適用日・確認範囲をPRまたはコミットの説明に記録し、[移植後の記載整理](#移植後の記載整理)に従って該当箇所を削除する。残る項目は「未適用」のままにする。
6. 本体と試作の対応を確認したファイルについて、取り込み基準を更新する。画像遷移を採用する場合は、変更したファイルを指定する。以下は投稿と画像ビューアを変更した場合の例。

   ```powershell
   python ui-prototype/import-production-ui.py --record app/src/main/java/io/github/ponpokoo/mastodonclient/feature/status/StatusCard.kt --record app/src/main/java/io/github/ponpokoo/mastodonclient/feature/media/MediaViewerScreen.kt
   ```

   `--record`は本体のハッシュを記録するだけで、コピー・マージ・テストを行わない。画像遷移など未適用の差分が残れば、記録後も`ADAPTED`が表示される。

完了とする条件は、選んだ変更が本体に入り、本体の画面・データと組み合わせた確認を終え、残る差分と未確認事項を区別できること。試作の確認だけで本体への適用済みにはしない。
